SDK добавляет три телеметрических параметра запроса к каждому исходящему запросу REST. Их имена стабильны между версиями; их значения позволяют сопоставлять запросы SDK на стороне Битрикс24 и на вашей инфраструктуре (журналы, трассировки, дашборды).

| Параметр | Источник | Примечания |
|----|----|----|
| `bx24_request_id` | `requestId`, который вы передаёте в `actions.v{2,3}.*.make({ requestId })`, или UUID v7, сгенерированный [`RequestIdGenerator`](/docs/tools/core-request-id-generator/), если он не указан. | Передаётся как параметр запроса и как заголовок `X-Request-ID`. Все три телеметрических параметра **пропускаются для прежних позиционных методов `task.*`** (`task.commentitem.*`, `task.checklistitem.*`, …) и в REST API v2, и в v3: эти методы читают строку запроса позиционно, поэтому Битрикс24 отклоняет вызов (`WRONG_ARGUMENTS`), когда параметры присутствуют. Современные `tasks.task.*` это ограничение не затрагивает. |
| `bx24_sdk_ver` | Константа времени сборки, подставляется `unbuild`. Равна версии в `package.json` пакета. | Позволяет Битрикс24 различать проблемы по версии SDK. |
| `bx24_sdk_type` | Константа времени сборки. Сейчас `b24-js-sdk`. | Отличает `b24jssdk` от других SDK (PHP, Python). |

## Имя заголовка

То же значение `bx24_request_id` помещается и в заголовок `X-Request-ID` (`DEFAULT_REQUEST_ID_HEADER_FIELD_NAME` в [`RequestIdGenerator`](/docs/tools/core-request-id-generator/)). Если ваш пограничный слой журналирует `X-Request-ID`, вы увидите один и тот же идентификатор в своих журналах и в журналах сервера Битрикс24.

## Настройка генератора

Если нужно унаследовать идентификатор трассировки вышестоящего сервиса (например, передать `X-Request-ID` из вашего шлюза), реализуйте [`IRequestIdGenerator`](/docs/tools/core-request-id-generator/) и внедрите его через собственную HTTP-настройку. Каждый вызов должен возвращать уникальное значение: по нему ведут учёт лимитер и журнал запросов.

## Всегда передавайте `requestId`

Хотя SDK генерирует его за вас, в продакшен-коде **всегда задавайте `requestId` явно**:

```ts
await $b24.actions.v2.call.make({
  method: 'crm.contact.get',
  params: { id: 123 },
  requestId: `contact-${123}-${Date.now()}`
})
```

Причины:

- Идентификатор появляется в выводе логгера SDK, что упрощает сопоставление.
- Идентификатор используется `RestrictionManager` для учёта повторов и задержек.
- Осмысленный идентификатор гораздо проще искать в обращениях в поддержку Битрикс24, чем UUID.
