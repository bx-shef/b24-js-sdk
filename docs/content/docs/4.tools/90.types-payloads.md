Типы в `types/payloads.ts` моделируют JSON-конверт, в который Битрикс24 оборачивает каждый ответ REST. Большинство кода приложений напрямую с ними не работает — помощники `actions.v{2,3}.*` разворачивают их и отдают вам [`SuccessPayload`](#successpayload) через `AjaxResult.getData()`. Они описаны здесь, потому что реэкспортируются из `@bxshefby/b24jssdk` и описывают «сырую» форму в сетевом обмене.

::note
REST API Битрикс24 оборачивает **успешный** ответ в `{ result, time }` и для `restApi:v2`, и для `restApi:v3`. Различия ниже ограничены конвертами *списков* и *пакетов*, у которых дополнительные поля постраничной загрузки существуют только в v2.
::

::warning
**Конверт — не универсален.** `rest.documentation.openapi` отвечает документом OpenAPI на **верхнем уровне** — без `result` и без `time`; измерено на коробочной сборке, облачном портале и облачной песочнице. `AjaxResult.getData()` оборачивает такое тело, чтобы `result` был самим документом; для `time` нечем его заполнить, и он остаётся `undefined`{lang="ts-type"}.
::

## `PayloadTime`

Блок времени, прикрепляемый к каждому конверту ответа. Присутствует и в v2, и в v3.

Два счётчика `operating*` **необязательны**, и их отсутствие — обычное состояние на портале на собственной инфраструктуре, а не крайний случай: портал добавляет их только пока активен его собственный лимитер, а в коробке он читает опцию модуля `rest` `load_limiter_active` — по умолчанию `N`, и ничто в продукте её не устанавливает. Этот же переключатель управляет принудительным применением, поэтому портал, не присылающий счётчики, ничего и не ограничивает. В таком случае SDK пропускает учёт времени операций и не выдумывает `0`, который нельзя было бы отличить от настоящего «пока ничего не израсходовано».

Ещё два наблюдения на сборке для собственной инфраструктуры, в которых разумное прочтение этих полей ошибается:

- **`operating_reset_at` может отсутствовать, когда `operating` присутствует**, а когда он *есть*, он означает либо срок действия сохранённых корзин, либо просто «начало этого запроса плюс окно» — по ответу отличить нельзя;
- **Наличие `operating` не означает, что он накапливается.** На портале, где лимитер включён, но хранилище не настроено, он приходит в каждом ответе и никогда не растёт.

Три состояния и то, как коробку вывести из среднего из них, см. в разделе [Лимитеры](/docs/tools/limiters/#@@Что означают счётчики, когда они приходят@@).

`duration` и `processing` **непригодны как измерения времени** на сборке, где это измерялось (`main 26.700.0`): портал усекает исходные метки времени до целых секунд, из-за чего `duration` завышается до секунды, а `processing` почти для каждого вызова показывает `0`. SDK измеряет собственные длительности и не читает ни одно из них.

```ts-type
type PayloadTime = {
  readonly start: number
  readonly finish: number
  readonly duration: number
  readonly processing: number
  readonly date_start: ISODate
  readonly date_finish: ISODate
  readonly operating_reset_at?: number // timestamp when part of the method limit is released
  readonly operating?: number          // execution time counted against the method limit
}
```

## `GetPayload`

Конверт для чтения одного элемента — обычная форма `{ result, time }`.

```ts-type
type GetPayload<P> = {
  readonly result: P
  readonly time?: PayloadTime
}
```

`time` здесь необязателен и связан с [`SuccessPayload`](#successpayload) ниже: `AjaxResult.getData()` возвращает `SuccessPayload`{lang="ts-type"} там, где контракт `IResult`{lang="ts-type"} ожидает `Payload`{lang="ts-type"}, поэтому этот член объединения должен оставаться совместимым с ним по присваиванию.

## `ListPayload`

Конверт для списочного метода **v2**. `total` и `next` — поля смещения постраничной загрузки v2.

```ts-type
type ListPayload<P> = {
  readonly result: P[]
  readonly total: number
  readonly next?: number
  readonly time: PayloadTime
}
```

::caution
`total` и `next` — **только v2**. `restApi:v3` использует постраничную загрузку по курсору, и прямого аналога в том же конверте у него нет. В исходниках `ListPayload` по-прежнему несёт метку `@todo ! add api3` — вариант конверта списка v3 **пока не смоделирован** как отдельный тип. Он вам не понадобится: `actions.v{2,3}.callList` / `fetchList` обходят страницы внутри, поэтому потребители читают агрегированный результат, а не `next` / `total`.
::

## `BatchPayload` / `BatchPayloadResult`

**Всё HTTP-тело** пакетного запроса: результаты, ошибки, итоги, следующие смещения и время каждого вызова — с ключами команд вызывающей стороны или по позиции.

::caution
Обратите внимание, чем этот тип является и чем не является. `BatchPayload<C>`{lang="ts-type"} описывает полное тело ответа `{ result: { … }, time }`{lang="ts-type"} — это **не** то, что возвращает `AjaxResult.getData().result`{lang="ts"} для пакетного вызова. `AjaxResult<X>`{lang="ts-type"} уже означает «тело — это `{ result: X, time }`{lang="ts-type"}», поэтому внутреннее значение описывает `BatchResponsePayload<T>`{lang="ts-type"} из [`core/interaction/batch/abstract-interaction-batch.ts`](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/core/interaction/batch/abstract-interaction-batch.ts). До v2.2.0 собственный транспорт SDK смешивал эти два типа и вынужден был обходить это приведением; эти типы экспортируются для справки и больше не используются внутри пакетной обработки.
::

```ts-type
type BatchPayloadResult<C> = {
  readonly result:
    | { readonly [P in keyof C]?: C[P] }
    | ReadonlyArray<C[keyof C]>
  readonly result_error:
    | { readonly [P in keyof C]?: string }
    | readonly string[]
  readonly result_total:
    | { readonly [P in keyof C]?: number }
    | readonly number[]
  readonly result_next:
    | { readonly [P in keyof C]?: number }
    | readonly number[]
  readonly result_time:
    | { readonly [P in keyof C]?: PayloadTime }
    | readonly PayloadTime[]
}

type BatchPayload<C> = {
  readonly result: BatchPayloadResult<C>
  readonly time: PayloadTime
}
```

::caution
`BatchPayloadResult` описывает конверт пакета **v2** и несёт в исходниках метку `@todo ! add api3`; вариант пакета v3 здесь пока не смоделирован. Предпочитайте `actions.v{2,3}.batch` / `batchByChunk`, которые разбирают этот конверт за вас.
::

## `SuccessPayload`

Публичная форма успешного ответа, возвращаемая `AjaxResult.getData()`. Это тип, который чаще всего видят потребители.

```ts-type
type SuccessPayload<P> = {
  readonly result: P
  readonly time?: PayloadTime
}
```

`result` есть всегда, потому что тело без ключа `result` **оборачивается** — всё тело становится `result`, а не отбрасывается. `time` так же заполнить нельзя, поэтому он необязателен: проверяйте его, прежде чем читать из него поле.

`SuccessPayload` намеренно имеет обычную форму `{ result, time }` — одинаковую для v2 и v3. Поля списков, существующие только в v2 (`next`, `total`), **намеренно исключены**: у них нет аналога в `restApi:v3`, а помощники `callList` / `fetchList` в SDK обрабатывают постраничную загрузку внутри, поэтому потребители никогда не читают их из конверта.

## `Payload`

Полный размеченный конверт, которым может быть «сырой» ответ, — либо описание ошибки (v2 или v3), либо один из описанных выше конвертов успеха.

```ts-type
type Payload<P> =
  | TypeDescriptionErrorV3   // v3 error envelope
  | TypeDescriptionError     // v2 error envelope
  | GetPayload<P>
  | ListPayload<P>
  | BatchPayload<P>
```

::note
`Payload` несёт в исходниках метку `@todo ! add api3 tail / add / update and etc`: варианты успеха, специфичные для v3 (постраничная загрузка tail, ответы add/update), ещё дорабатываются. Ветви ошибок уже моделируют обе версии — `TypeDescriptionError` (v2) и `TypeDescriptionErrorV3` (v3), оба определены в [`types/auth.ts`](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/types/auth.ts).
::

## Связанное

- [`IResult` / `AjaxResult`](/docs/tools/types-iresult/) — `AjaxResult.getData()` при успехе возвращает `SuccessPayload<T>`.
- [`AjaxResult`](/docs/tools/core-ajax-result/) — декодирует «сырой» конверт `Payload`, включая ветви ошибок.
- [Общие типы](/docs/tools/types-common/) — `ISODate` и псевдонимы скаляров, используемые внутри этих конвертов.
