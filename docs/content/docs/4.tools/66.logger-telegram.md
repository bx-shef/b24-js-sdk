### Использование на стороне сервера
```ts
import { LogLevel, Logger, TelegramHandler } from '@bxshefby/b24jssdk'

// Create a logger with Telegram handler
const $logger = new Logger('my-app')

const telegramHandler = new TelegramHandler(LogLevel.ERROR, {
  botToken: 'YOUR_BOT_TOKEN',
  chatId: 'YOUR_CHAT_ID',
  parseMode: 'HTML', // or 'MarkdownV2'
  disableNotification: false, // Send notifications
  disableWebPagePreview: true // Disable link previews
});

$logger.pushHandler(telegramHandler)

// Now critical errors will be sent to Telegram
$logger.error('Payment service unavailable', {
  service: 'stripe',
  error: 'Connection timeout',
  duration: '30s'
})
```

### Использование на стороне клиента

:::caution
На стороне клиента обработчик не поддерживается по соображениям безопасности: запрос содержит
токен бота в адресе, а клиентский код доступен для чтения.

**Это относится и к воркеру.** У Web, Shared и Service Worker нет DOM, но их скрипт загружается
по сети и читается так же, как страница, — поэтому `handle()` ничего не отправляет и предупреждает,
а `testConnection()` отказывается обращаться к Telegram. До версии `3.0.0` воркер попадал в ветку
неизвестной среды: предупреждения не было, а `testConnection()` выполнил бы запрос.

Передайте `warnInBrowser: false`, чтобы отключить предупреждение в консоли (обработчик по-прежнему
ничего не отправляет).

**Не регистрируйте этот обработчик в коде, который попадает в браузер или воркер.**
Отказ зависит от того, что SDK распознаёт среду выполнения, а среду можно выдать за серверную:
браузерный воркер со сборкой полифила `process`, сообщающего версию Node, будет принят за
сервер, и обработчик отправит запрос. Определение среды — это страховка, а не граница;
токену место на сервере.
:::
