## Обзор

Несколько небольших помощников без зависимостей, которые SDK использует для преобразования объектов и сужения типов. Все четыре — обычные функции, экспортируемые из `@bxshefby/b24jssdk`:

- **`pick`** — новый объект, содержащий только перечисленные ключи.
- **`omit`** — поверхностная копия без перечисленных ключей.
- **`getEnumValue`** — преобразует «сырую» строку или число в соответствующий член перечисления (или `undefined`).
- **`isArrayOfArray`** — защита типа, отличающая массив массивов от плоского массива.

```ts
import { pick, omit } from '@bxshefby/b24jssdk'

const user = { ID: '1', NAME: 'Ann', EMAIL: 'ann@example.com' }

pick(user, ['ID', 'NAME']) // { ID: '1', NAME: 'Ann' }
omit(user, ['EMAIL'])      // { ID: '1', NAME: 'Ann' }
```

## Сигнатура метода

```ts-type
pick<Data extends object, Keys extends keyof Data>(
  data: Data,
  keys: Keys[]
): Pick<Data, Keys>

omit<Data extends object, Keys extends keyof Data>(
  data: Data,
  keys: Keys[]
): Omit<Data, Keys>

getEnumValue<T extends Record<string, string | number>>(
  enumObj: T,
  value: string | number
): T[keyof T] | undefined

isArrayOfArray<A>(item: A[] | A[][]): item is A[][]
```

## Ключевые понятия

- **`pick` / `omit` работают поверхностно.** `pick` копирует ссылки на выбранные свойства в новый объект; `omit` разворачивает `data` в поверхностный клон и выполняет `delete` для перечисленных ключей. Вложенные объекты разделяются по ссылке, а исходный `data` никогда не изменяется. Оба возвращают точно типизированный результат (`Pick<Data, Keys>` / `Omit<Data, Keys>`).
- **`getEnumValue` — поиск во время выполнения.** Он проверяет, есть ли `value` в `Object.values(enumObj)`, и если есть, возвращает его суженным до типа члена перечисления; иначе возвращает `undefined`. Работает и со строковыми, и с числовыми перечислениями и является безопасным способом превратить недоверенную строку из REST в типизированный член перечисления.
- **`isArrayOfArray` проверяет только первый элемент.** Он возвращает `Array.isArray(item[0])` и не просматривает весь массив. Для пустого массива `item[0]` равен `undefined`, поэтому возвращается `false`. SDK использует его, чтобы отличить один список пакетных вызовов от списка списков.

## Обработка ошибок

Ни один из этих помощников не выбрасывает исключений. `pick` / `omit` работают с копией и не трогают входные данные, `getEnumValue` возвращает `undefined` для значения, не являющегося членом перечисления, а `isArrayOfArray` для пустого массива возвращает `false`, а не завершается сбоем.

## Примеры

Преобразование записи REST перед отправкой дальше:

```ts
import { pick, omit } from '@bxshefby/b24jssdk'

const contact = { ID: '42', NAME: 'Ann', PHONE: '+100', SECRET: 'x' }

// Оставить только то, что нужно следующему вызову
pick(contact, ['ID', 'NAME']) // { ID: '42', NAME: 'Ann' }

// Убрать внутреннее поле перед записью в журнал
omit(contact, ['SECRET']) // { ID: '42', NAME: 'Ann', PHONE: '+100' }
```

Преобразование «сырого» типа поля в член `DataType`:

```ts
import { getEnumValue, DataType } from '@bxshefby/b24jssdk'

getEnumValue(DataType, 'string') // DataType.string
getEnumValue(DataType, 'nope')   // undefined
```

Ветвление по форме массива с помощью защиты типа:

```ts
import { isArrayOfArray } from '@bxshefby/b24jssdk'

isArrayOfArray([[1, 2], [3, 4]]) // true  — массив массивов
isArrayOfArray([1, 2, 3])        // false — плоский массив
isArrayOfArray([])               // false — пустой массив
```

## Альтернативы и рекомендации

- **Используйте `getEnumValue` с перечислениями из [`types/common`](/docs/tools/types-common/).** Он естественно сочетается с [`DataType`](/docs/tools/types-common/) и любым другим перечислением SDK, когда нужно проверить «сырую» строку REST, прежде чем считать её типизированным значением.
- **Для небольших явных преобразований предпочитайте `pick` / `omit`.** Они поверхностные по замыслу; для глубокого клонирования или сложных преобразований используйте специальную утилиту, а не наслаивайте эти.
- **`isArrayOfArray` — эвристика, а не валидатор.** Он доверяет первому элементу как представителю всего массива — не используйте его для проверки смешанных или недоверенных данных, где последующие элементы могут отличаться по форме.
- **Проверки типов скалярных значений находятся в [`Type`](/docs/tools/type/).** `isArrayOfArray` отвечает на один узкий вопрос о вложенности массивов; для общих проверок формы используйте защиты `Type` (`isArrayFilled`, `isStringFilled`, …).
