`Result<T>`{lang="ts-type"} — единый возвращаемый тип SDK для помощников более высокого уровня (`callBatch`, `B24HelperManager.loadData`, `OptionsManager.save`, …). Класс реализует `IResult<T>`{lang="ts-type"}; типизированные REST-помощники (`call.make`, `callList.make`, …) возвращают его специализированный подкласс [`AjaxResult<T>`](/docs/working-with-the-rest-api/core-ajax-result/).

## Использование

```ts
import { Result } from '@bitrix24/b24jssdk'

function parseConfig(raw: string): Result<{ theme: string }> {
  try {
    const data = JSON.parse(raw)
    if (typeof data?.theme !== 'string') {
      return Result.fail<{ theme: string }>('theme is required', 'config:theme')
    }
    return Result.ok({ theme: data.theme })
  } catch (error) {
    return Result.fail<{ theme: string }>(error as Error, 'config:json')
  }
}

function applyConfig() {
  const rawJson = '{"theme":"light"}'
  const result = parseConfig(rawJson)
  if (!result.isSuccess) {
    console.error(result.getErrorMessages())
    return
  }
  const { theme } = result.getData()!
  console.log('theme:', theme)
}
applyConfig()
```

## Конструктор

```ts-type
new Result<T>(data?: T)
```

`data` по умолчанию равен `null`{lang="ts-type"}.

## Статические фабрики

```ts-type
Result.ok<U>(data?: U): Result<U>
Result.fail<U>(error: Error | string, key?: string): Result<U>
```

## Геттеры

| Геттер | Тип | Описание |
|----|----|----|
| `isSuccess` | `boolean`{lang="ts-type"} | `true`, когда карта ошибок пуста. |
| `errors` | `Map<string, Error>`{lang="ts-type"} | Внутреннее хранилище ошибок (по соглашению только для чтения). |

## Методы данных

```ts-type
setData(data: T | null | undefined): this
getData(): T | null | undefined
```

`setData` поддерживает цепочки вызовов. Изменяющие методы возвращают полиморфный `this`{lang="ts-type"}, а не `Result<T>`{lang="ts-type"}, поэтому цепочка от подкласса остаётся подклассом: `ajaxResult.addError(e).getStatus()`{lang="ts"} по-прежнему работает. До v2.2.0 они объявлялись как `Result<T>`{lang="ts-type"}, и цепочка теряла всё, что добавляет `AjaxResult`{lang="ts-type"}. Примечание: `AjaxResult`{lang="ts-type"} **отключает** `setData` и при вызове выбрасывает `ReferenceError`{lang="ts-type"}.

## Методы ошибок

```ts-type
addError(error: Error | string, key?: string): this
addErrors(errors: (Error | string)[]): this
hasError(key: string): boolean
getErrors(): IterableIterator<Error>
getErrorMessages(): string[]
getErrorsByKey(): Record<string, Error>
getErrorMessagesByKey(): Record<string, string>
```

Если `key` не указан, `addError` генерирует UUID v7 через [`Text.getUuidRfc4122()`](/docs/working-with-the-rest-api/tools-text/), чтобы одинаковые строки получали разные ячейки.

`getErrorsByKey()` / `getErrorMessagesByKey()` возвращают **снимок** `Record`{lang="ts-type"} с этим идентификатором в качестве ключа, так что видно, какой вызов завершился ошибкой — в отличие от `getErrors()` / `getErrorMessages()`, которые отбрасывают ключи, и от «живого» геттера `errors` (`Map`{lang="ts-type"}). Для пакетных запросов ключ показывает, какая команда завершилась ошибкой: пакет с **объектом / именованными командами** использует в качестве ключа метку команды, а пакет в **режиме массива** — **числовую позицию** команды (`'0'`, `'1'`, … — начиная с v1.4.0 / [#255](https://github.com/bitrix24/b24jssdk/issues/255); раньше это были случайные UUID). Мягкая ошибка уровня конверта, не привязанная к одной команде, использует внутренний ключ `base-error`, а `addErrors()` (без явного ключа) по-прежнему использует сгенерированные UUID — для них лучше `getErrors()` / `getErrorMessages()`.

```ts
const res = await $b24.actions.v2.batch.make({
  calls: {
    contact: { method: 'crm.item.get', params: { entityTypeId: 3, id: 1 } },
    deal: { method: 'crm.item.get', params: { entityTypeId: 2, id: 999 } }
  },
  options: { isHaltOnError: false }
})
if (!res.isSuccess) {
  console.error(res.getErrorMessagesByKey()) // e.g. { deal: 'Access denied' }
}
```

## `toString`

```ts-type
toString(): string
```

Форматирует результат для журнала:

- успех → `Result(success): {<data JSON>}`
- сбой → `Result(failure): {<data JSON>}\nErrors: <messages joined by ", ">`

Экземпляры `Error` внутри данных сериализуются как `{ name, message, stack }`. Если сериализовать не удаётся, используется `'[Unable to serialize data]'`.
