::note
Обычно вы используете `actions.v2.*` / `actions.v3.*` и не обращаетесь к `TypeHttp`{lang="ts-type"} напрямую. Он нужен, когда требуются «сырые» `call` / `batch`, тонкая настройка лимитера или статистика во время выполнения.
::

`TypeHttp`{lang="ts-type"} — контракт, который реализуют `HttpV2`{lang="ts-type"} и `HttpV3`{lang="ts-type"}. Каждый `B24Frame`{lang="ts-type"} / `B24Hook`{lang="ts-type"} / `B24OAuth`{lang="ts-type"} владеет одним экземпляром на каждую версию REST API. Доступ к ним:

```ts
import { ApiVersion } from '@bxshefby/b24jssdk'

const v2 = $b24.getHttpClient(ApiVersion.v2)
const v3 = $b24.getHttpClient(ApiVersion.v3)
```

## Свойства

| Свойство | Тип | Описание |
|----|----|----|
| `apiVersion` | `ApiVersion`{lang="ts-type"} | `ApiVersion.v2` или `ApiVersion.v3`. |
| `ajaxClient` | `AxiosInstance`{lang="ts-type"} | Базовый экземпляр axios. Используйте его для не-REST-вызовов к тому же источнику. |

## Логгер

setLogger(logger: LoggerInterface): void

Позволяет подставить отладочный логгер в один клиент, не затрагивая остальной SDK. См. [Logger](/docs/tools/logger/).

## Вызов REST

### `call`

```ts-type
call<T = unknown>(
  method: string,
  params: TypeCallParams,
  requestId?: string
): Promise<AjaxResult<T>>
```

Низкоуровневый вызов одного метода. Помощники более высокого уровня (`actions.v2.call.make`, `callList`, `fetchList`) строятся поверх него.

### `batch`

```ts-type
batch<T = unknown>(
  calls: BatchCommandsArrayUniversal | BatchCommandsObjectUniversal | BatchNamedCommandsUniversal,
  options?: ICallBatchOptions
): Promise<Result<ICallBatchResult<T>>>
```

Низкоуровневый пакетный вызов (batch). Принимаются три формы входных данных:

- массив кортежей: `[ [method, params], [method, params] ]`;
- массив объектов: `[ { method, params, as?, parallel? }, ... ]`;
- именованная карта: `{ key1: { method, params }, key2: [method, params] }`.

`params` — единственный ключ, из которого читаются аргументы команды: если записать их под `query`, как называет их сам портал, они молча потеряются. См. предупреждение на страницах [BatchV3](/docs/actions/batch/) и [BatchV2](/docs/actions/batch/) — два транспорта теряют их разными путями.

В большинстве случаев вызывайте [`actions.v2.batch.make`](/docs/actions/batch/) / [`actions.v3.batch.make`](/docs/actions/batch/): они сами разворачивают ответ и учитывают `returnAjaxResult`.

::note
`BatchRequestEnvelopeV2`{lang="ts-type"} экспортируется вместе с этими типами, но создавать его самостоятельно не нужно. Он называет то, что транспорт `restApi:v2` отправляет по сети для пакета, — `{ halt, cmd }`; это попадает в `call` через параметр типа `TypeCallParams`{lang="ts-type"} и проходит проверку типов только благодаря свободной индексной сигнатуре этого типа. Он описан здесь, чтобы экспортируемый символ не оставался загадкой, а не потому, что он нужен вызывающему коду. В `restApi:v3` конверта нет: команды **и есть** тело запроса — голый JSON-массив верхнего уровня. Поэтому в теле нет места для учётных данных — портал читает каждый элемент верхнего уровня как команду, — так что вебхук хранит секрет в URL, а серверный `B24OAuth` передаёт токен в заголовке `Authorization: Bearer`. Браузер такой заголовок отправить не может (CORS-предзапрос портала его не разрешает), поэтому пакет v3 не работает из `B24Frame`; см. [ограничения BatchV3](/docs/actions/batch/#ограничения).
::

## Настройка экземпляра axios

`ajaxClient` — действующий экземпляр axios, который использует транспорт. Попасть в него можно двумя способами. `httpOptions` при создании объединяются с собственными значениями SDK по умолчанию — именно туда относится `adapter`; всё остальное можно изменить после создания клиента через `defaults`:

```ts
import { B24Hook } from '@bxshefby/b24jssdk'

const b24 = B24Hook.fromWebhookUrl(
  'https://your-portal.bitrix24.com/rest/1/SECRET',
  { httpOptions: { adapter: 'xhr' } }
)
```

Встроенное приложение передаёт ту же опцию в `initializeB24Frame()`, который без изменений пересылает её в конструктор `B24Frame`, — и именно в браузере `adapter` приносит пользу, потому что адаптер изменился именно в этой среде выполнения. Побеждает **первый** вызов: последующий `initializeB24Frame()` возвращает уже построенный фрейм и игнорирует свои `options`.

```ts
import { initializeB24Frame } from '@bxshefby/b24jssdk'

const $b24 = await initializeB24Frame({ httpOptions: { adapter: 'xhr' } })
```

`httpOptions` — намеренно узкая часть `AxiosRequestConfig`{lang="ts-type"}, то есть `TypeHttpOptions`{lang="ts-type"}: `adapter`, `timeout`, `timeoutErrorMessage`, `proxy`, `httpAgent`, `httpsAgent`, `maxRedirects`, `maxContentLength`, `maxBodyLength`, `decompress`, `withCredentials`. `baseURL`, `transformRequest`, `paramsSerializer` и `validateStatus` — это способ, которым SDK общается с порталом, и их переопределение незаметно ломает работу: `transformRequest`{lang="ts-type"} здесь целиком заменяет тело запроса, без ошибки с любой стороны, а сбой проявляется только на стороне портала, — поэтому они не предлагаются, а ключ вне списка **отбрасывается при создании**, причём имена отброшенных ключей попадают в журнал (значения — никогда). Одного типа для этого недостаточно: проверка лишних свойств не срабатывает на переменной, а в обычном JavaScript компилятора нет вовсе. Через `defaults` ниже они остаются доступны, и это выглядит так, как есть, — осознанным действием.

::note
**Список защищает от случайной поломки SDK — это не граница безопасности.** `adapter` целиком заменяет транспорт, а это строго больше, чем мог бы исключённый `transformRequest`, а `proxy` / `httpAgent` направляют трафик с токенами туда, куда вы укажете. Оба входят в список, потому что `adapter` — причина его существования. Фильтр также действует только на два REST-транспорта: клиент обновления токена OAuth создаёт собственный экземпляр axios, поэтому `adapter`, `timeout` и `proxy` не применяются к запросу, который отправляет `client_secret` на сервер OAuth.
:: `headers` — единственное исключение, да и то не предлагаемое: `TypeHttpOptions`{lang="ts-type"} его не принимает, поэтому `httpOptions: { headers: … }` — ошибка компиляции. Само объединение сохраняется для пути, который появился раньше этого типа, — прямого `new HttpV2(...)` или вызова из нетипизированного JavaScript, как и с #144.

```ts
import { ApiVersion } from '@bxshefby/b24jssdk'

const http = $b24.getHttpClient(ApiVersion.v3)

http.ajaxClient.defaults.timeout = 120_000
http.ajaxClient.defaults.proxy = { host: '10.0.0.1', port: 3128 }
```

Четыре вещи, которые задаёт SDK и о которых нужно знать, прежде чем их переопределять:

- **`timeout: 30_000`** и соответствующий `timeoutErrorMessage`. Для долгого отчётного метода увеличьте его, а не число повторов. Сообщение читают только адаптеры XHR и Node; в `fetch` axios формирует собственное (`timeout of 30000ms exceeded`, код `ETIMEDOUT`, а не `ECONNABORTED`). SDK в любом случае распознаёт оба варианта как тайм-аут.
- **`User-Agent`** — только в серверных средах выполнения: браузер **и воркер** запрещают этот заголовок, поэтому ни там, ни там он не задаётся.
- **`Content-Type: application/json`** — для каждого запроса, а не на экземпляре. Портал читает булев `filter` только из JSON-тела, а axios подставлял этот тип содержимого по умолчанию, а не по замыслу — см. [Фильтрация](/docs/actions/filtering/). Поскольку он задаётся для каждого запроса, `ajaxClient.defaults.headers` больше не влияет на трафик SDK; ваши собственные запросы через этот экземпляр не затронуты, в том числе с телом `FormData`, границу multipart для которого axios по-прежнему вычисляет сам. **Перехватчик запросов (request interceptor)**, установленный на этом экземпляре, всё равно имеет приоритет — он выполняется после сборки конфигурации, — поэтому перехватчик, который задаёт `Content-Type`, меняет кодирование и трафика SDK, а значит, и описанное выше поведение булева фильтра.
- **`adapter: 'fetch'` — только в браузере или воркере.** Если ничего не указывать, axios перебирает `['xhr', 'http', 'fetch']` и берёт первый поддерживаемый вариант — XHR везде, где есть `XMLHttpRequest`. Вне браузера ничего не запрашивается.

::note
**Из-за адаптера есть два следствия, если вы сами работаете с этим экземпляром.**
Набор тестов под `jsdom` считается здесь браузером, поэтому подмена, которая заглушает `XMLHttpRequest`, перестаёт перехватывать трафик SDK — передайте в таком наборе `httpOptions: { adapter: 'xhr' }`. Кроме того, axios включает `onUploadProgress` только при потоковой отправке запроса, которую поддерживает лишь Chromium по HTTP/2: ваши собственные загрузки через `ajaxClient` не получат событий прогресса в Firefox и Safari, где XHR всегда их доставлял. Отказ от этого — тот же.
::

::warning
**`maxRedirects` принудительно равен `0` только там, где учётные данные передаются вне тела.** Пакет `restApi:v3` или вызов `restApi:v3` с `idempotencyKey` на не-вебхук-транспорте вне браузера несёт токен доступа в заголовке `Authorization: Bearer`, и перенаправление унесло бы его с собой (скачивание файла результата `actions.v3.deferredBatch` тоже отказывается от перенаправлений, поскольку сам его URL — учётные данные): `follow-redirects` удаляет заголовок при смене хоста, но сохраняет его для того же хоста и для **поддомена**. Учётные данные в теле здесь были в безопасности случайно: 301/302 превращает POST в GET и отбрасывает тело, поэтому токен, который раньше лежал в `auth`, никуда не уходил.

По умолчанию ограничение действует на запрос, а не на экземпляр: остальное, что отправляет SDK, не затронуто, а перенаправление в другом месте вашего трафика по-прежнему работает. Портал, который всё же перенаправляет именно этот запрос, получает понятный ответ 301 вместо тихого перехода с приложенным токеном.

**В браузере соседняя ветка ведёт себя иначе**, и с появлением адаптера `fetch` она больше не бездействует. Там токен передаётся в строке запроса, а не в заголовке, `maxRedirects: 0` задаётся по той же причине, а `fetch` читает его как `redirect: 'manual'`, тогда как XHR его вообще игнорировал. В ответ приходит **непрозрачный (opaque)** ответ — `status: 0`{lang="ts-type"}, пустое тело, без заголовков, — и axios его *разрешает*: `settle` рано завершается при любом ложном статусе, до обращения к `validateStatus`, а в адаптере fetch нет собственной защиты от статуса 0 (в XHR она была). В таком виде отклонённый запрос выглядел бы как молча пустой успех, поэтому SDK сам выбрасывает `JSSDK_HTTP_REDIRECT_BLOCKED` — только для запроса, который просил `maxRedirects: 0`, так что обычный сбой сети со статусом 0 не затрагивается. Область та же узкая: пакет `restApi:v3` или вызов `restApi:v3` с `idempotencyKey` на не-вебхук-транспорте.

Если вы знаете цель перенаправления и всё же хотите перейти по ней, подкласс транспорта может вернуть `maxRedirects` из `_prepareRequestConfig`, и это значение победит: оно задаётся по умолчанию, до наложения конфигурации запроса, а не жёстко. Установка `ajaxClient.defaults.maxRedirects` до него **не** доходит: в axios конфигурация запроса важнее значения по умолчанию на экземпляре.
::

## Настройка лимитера

```ts-type
setRestrictionManagerParams(params: RestrictionParams): Promise<void>
getRestrictionManagerParams(): RestrictionParams
```

Обновляет или читает политику ограничений **этого** клиента. Сеттер заменяет указанные вами параметры и не трогает остальные, а вложенные блоки лимитеров заменяются целиком — см. [Обновление параметров](/docs/tools/limiters/#обновление-параметров). Геттер возвращает копию. Чтобы изменить сразу v2 и v3, используйте `b24.setRestrictionManagerParams(...)`.

Форму параметров и пресеты (`ParamsFactory.getDefault()`, `getBatchProcessing()`, `getRealtime()`, `fromTariffPlan()`) см. в разделе [Лимитеры](/docs/tools/limiters/).

getStats(): RestrictionManagerStats & {

## Сброс

```ts-type
reset(): Promise<void>
```

Очищает состояние лимитера и статистику. Типичное применение — после аварийного восстановления или в долгоработающих демонах, которым нужно чистое окно.

## Предупреждение для клиентской стороны

```ts-type
setClientSideWarning(value: boolean, message: string): void
```

`B24Hook`{lang="ts-type"} и `B24OAuth`{lang="ts-type"} включают предупреждение времени выполнения при использовании в среде, похожей на браузерную, — в основном потоке или любом воркере (их секреты никогда не должны попадать на клиент, а сборка воркера так же публична, как страница). Переключайте его через родительский класс — `b24.offClientSideWarning()`; этот метод — базовый примитив.
