Типы в `types/common.ts` — небольшой общий словарь, на котором построен остальной SDK: строковые псевдонимы, описывающие, как Битрикс24 кодирует скаляры в REST, формы метаданных, возвращаемых вызовами `*.fields`, и перечисление `DataType`{lang="ts-type"}. Всё это реэкспортируется из `@bxshefby/b24jssdk`.

## Псевдонимы скаляров

Это обычные псевдонимы `string` (или строковых литералов). Поведения во время выполнения у них нет — они документируют, как Битрикс24 кодирует значение, чтобы места вызова читались понятно.

```ts-type
type NumberString = string        // a number sent as text, e.g. '20.23'
type ISODate = string             // ISO 8601 datetime, e.g. '2018-06-07T03:00:00+03:00'
type BoolString = 'Y' | 'N'       // Bitrix24's boolean encoding
type GenderString = 'M' | 'F' | ''

type PlacementViewMode = 'view' | 'edit'
type TextType = 'text' | 'html'
```

```ts
import type { NumberString, BoolString, ISODate } from '@bxshefby/b24jssdk'

interface DealRow {
  ID: NumberString      // '42'
  OPENED: BoolString    // 'Y' | 'N'
  DATE_CREATE: ISODate  // '2018-06-07T03:00:00+03:00'
}
```

## Формы метаданных полей

### `Fields`

Форма ответа `*.fields` — карта имени поля на его метаданные. Каждая запись помечена `readonly`.

```ts-type
type Fields = {
  readonly [key: string]: {
    readonly type: string
    readonly isRequired: boolean
    readonly isReadOnly: boolean
    readonly isImmutable: boolean
    readonly isMultiple: boolean
    readonly isDynamic: boolean
    readonly title: string
    readonly upperName?: string
  }
}
```

### `MultiField` / `MultiFieldArray`

**Где вы с этим столкнётесь:** поля контакта с несколькими значениями (телефон, email, мессенджер, сайт, …), которые возвращают сущности CRM, например `crm.contact.get`. Каждое значение несёт собственный идентификатор и уточнение типа значения (`WORK`, `HOME`, …). `MultiFieldArray` — усечённая форма, используемая при **записи** этих полей обратно: нужны только `VALUE` и `VALUE_TYPE`.

```ts-type
type MultiField = {
  readonly ID: NumberString
  readonly VALUE_TYPE: string
  readonly VALUE: string
  readonly TYPE_ID: string
}

type MultiFieldArray = ReadonlyArray<
  Pick<MultiField, 'VALUE' | 'VALUE_TYPE'>
>
```

### `UserFieldType`

**Где вы с этим столкнётесь:** описывает встроенные настройки пользовательского поля (UF) — `USER_TYPE_ID`, его обработчик и метаданные отображения. Передаётся при регистрации или отображении пользовательского типа поля.

```ts-type
type UserFieldType = {
  USER_TYPE_ID: string
  HANDLER: string
  TITLE: string
  DESCRIPTION: string
  OPTIONS?: {
    height: number
  }
}
```

## Перечисление `DataType`

**Где используется:** канонические типы данных полей Битрикс24 (см. [справочник типов данных](https://apidocs.bitrix24.ru/api-reference/data-types.html)). Оно сопоставляет строку `type` поля со стабильным членом перечисления, чтобы код мог ветвиться по `DataType.date`, `DataType.crmStatus`, … вместо «магических» строк.

```ts-type
enum DataType {
  undefined = 'undefined',
  any = 'any',
  integer = 'integer',
  boolean = 'boolean',
  double = 'double',
  date = 'date',
  datetime = 'datetime',
  string = 'string',
  text = 'text',
  file = 'file',
  array = 'array',
  object = 'object',
  user = 'user',
  location = 'location',
  crmCategory = 'crm_category',
  crmStatus = 'crm_status',
  crmCurrency = 'crm_currency'
}
```

Преобразуйте «сырую» строку `type` в член перечисления с помощью [`getEnumValue`](/docs/tools/object-helpers/):

```ts
import { getEnumValue, DataType } from '@bxshefby/b24jssdk'

getEnumValue(DataType, 'crm_status') // DataType.crmStatus
getEnumValue(DataType, 'unknown')    // undefined
```

## Связанное

- [`getEnumValue`](/docs/tools/object-helpers/) — превращает «сырую» строку REST в типизированный член перечисления `DataType` (или любого другого).
- [Типы полезной нагрузки](/docs/tools/types-payloads/) — конверт ответа REST, оборачивающий результаты, построенные из этих скаляров.
- [`Text`](/docs/tools/text/) — `toB24Format` создаёт строки `ISODate`, которых ожидает API.
