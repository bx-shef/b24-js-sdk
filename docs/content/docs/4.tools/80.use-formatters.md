## Обзор

`useFormatter()`{lang="ts-type"} — композабл, экспортируемый из `@bitrix24/b24jssdk`. Он возвращает два общих форматтера-синглтона:

- **`formatterNumber`** — экземпляр `FormatterNumbers`, учитывающая локаль обёртка над `Intl.NumberFormat`.
- **`formatterIban`** — экземпляр `FormatterIban` с предзагруженными спецификациями IBAN по странам: все страны официального реестра IBAN, несколько неофициальных стран, следующих структуре IBAN, и французские регионы и административные образования (GF, GP, MQ, RE, PF, TF, YT, NC, BL, MF, PM).

Оба форматтера — синглтоны (`FormatterNumbers.getInstance()` / `FormatterIban.getInstance()`), поэтому каждый вызов `useFormatter()` возвращает одни и те же экземпляры: состояние, заданное в одном (например, локаль по умолчанию), видно везде в приложении. `useFormatter()` повторно регистрирует спецификации IBAN при каждом вызове, но так как `formatterIban` — синглтон, а `addSpecification` просто перезаписывает запись карты для кода страны, повторные вызовы `useFormatter()` дёшевы.

```ts
import { useFormatter } from '@bitrix24/b24jssdk'

const { formatterNumber, formatterIban } = useFormatter()

console.log(formatterIban.printFormat('GB29NWBK60161331926819'))
// 'GB29 NWBK 6016 1331 9268 19'

console.log(formatterIban.isValid('DE89370400440532013000'))
// true

console.log(formatterNumber.format(1234.567))
// '1,234.57'
```

## Сигнатура метода

### `useFormatter()`

```ts-type
useFormatter(): {
  formatterNumber: FormatterNumbers
  formatterIban: FormatterIban
}
```

### `FormatterNumbers`

```ts-type
setDefLocale(locale: string): void
format(value: number, locale?: string): string
```

### `FormatterIban`

```ts-type
addSpecification(spec: IbanSpecification): void

isValid(iban: string): boolean
printFormat(iban: string, separator?: string): string     // default separator ' '
electronicFormat(iban: string): string                     // strips non-alphanumerics, uppercases

toBBAN(iban: string, separator?: string): string           // default separator ' '
fromBBAN(countryCode: string, bban: string): string
isValidBBAN(countryCode: string, bban: string): boolean
```

## Ключевые понятия

::note
`FormatterNumbers.format` выбирает локаль в таком порядке: явный аргумент `locale`, затем локаль, заданная через `setDefLocale`, затем `navigator.language` (только в браузере), затем возвращается к `'en'`. Целые числа форматируются с 0 знаков после запятой, нецелые — ровно с 2. Если выбранная локаль содержит `'ru'`, десятичная запятая, которую даёт `Intl.NumberFormat`, заменяется точкой.
::

::note
`FormatterIban.isValid` и методы BBAN (`toBBAN`, `fromBBAN`, `isValidBBAN`) выбрасывают `Error('No country with code XX')`, если для кода страны IBAN или BBAN не зарегистрирована `IbanSpecification`. Поскольку `useFormatter()` уже регистрирует все поддерживаемые страны, это происходит только для действительно неподдерживаемых или некорректных кодов стран.
::

- **`isValid` принимает свободно отформатированный ввод.** Сначала он пропускает IBAN через `electronicFormat`, поэтому пробелы и строчные буквы нормализуются до проверки длины, структуры и контрольной суммы ISO 7064 MOD 97-10 для конкретной страны. Нестроковый ввод возвращает `false`, а не выбрасывает исключение.
- **`printFormat` и `toBBAN` сначала нормализуют через `electronicFormat`**, поэтому принимают тот же свободно отформатированный ввод, что и `isValid`.
- **`addSpecification` перезаписывает по коду страны.** Повторный вызов для уже зарегистрированной страны (как делает `useFormatter()` при каждом вызове) просто заменяет существующую `IbanSpecification` — запись не накапливается и исключения не выбрасывает.
- **`FormatterNumbers` и `FormatterIban` нельзя создать напрямую.** Оба класса защищают конструктор, и синглтон создаёт только `getInstance()`; всегда получайте их через `useFormatter()`.

## Обработка ошибок

Сам `useFormatter()` никогда не выбрасывает исключение. `FormatterIban.isValid` возвращает `false` для некорректного или нестрокового ввода, а не выбрасывает исключение. Помощники BBAN (`toBBAN`, `fromBBAN`, `isValidBBAN`) и путь расчёта контрольной суммы выбрасывают `Error('No country with code XX')` только для кода страны, у которого нет зарегистрированной `IbanSpecification`, — а `useFormatter()` такого никогда не создаёт, поскольку регистрирует каждую поддерживаемую страну при каждом вызове. `FormatterNumbers` делегирует работу `Intl.NumberFormat`, который выбрасывает `RangeError` для недопустимой локали или опции, а не для числового ввода.

## Примеры

Проверка и форматирование IBAN:

```ts
import { useFormatter } from '@bitrix24/b24jssdk'

const { formatterIban } = useFormatter()

formatterIban.isValid('DE89370400440532013000') // true
formatterIban.isValid('GB29NWBK60161331926818') // false (bad checksum)

formatterIban.printFormat('GB29NWBK60161331926819') // 'GB29 NWBK 6016 1331 9268 19'
formatterIban.printFormat('GB29NWBK60161331926819', '-') // 'GB29-NWBK-6016-1331-9268-19'

// Accepts loosely formatted input (spaces, lower case)
formatterIban.electronicFormat('GB29 NWBK 6016 1331 9268 19') // 'GB29NWBK60161331926819'
```

Преобразование между IBAN и BBAN:

```ts
import { useFormatter } from '@bitrix24/b24jssdk'

const { formatterIban } = useFormatter()

formatterIban.toBBAN('GB29NWBK60161331926819') // 'NWBK 601613 31926819'
formatterIban.toBBAN('GB29NWBK60161331926819', '-') // 'NWBK-601613-31926819'

formatterIban.isValidBBAN('GB', 'NWBK60161331926819') // true
formatterIban.fromBBAN('GB', 'NWBK60161331926819') // 'GB29NWBK60161331926819'
```

Форматирование чисел с учётом локали:

```ts
import { useFormatter } from '@bitrix24/b24jssdk'

const { formatterNumber } = useFormatter()

formatterNumber.format(1234) // '1,234' (integer, 'en' default)
formatterNumber.format(1234.567) // '1,234.57' (rounded to 2 decimals)
formatterNumber.format(1234.5, 'de') // '1.234,50'

formatterNumber.setDefLocale('ru')
formatterNumber.format(1234.5) // '1 234.50' (ru grouping, dot kept instead of comma)
```

## Альтернативы и рекомендации

- **Используйте `formatterIban.isValid`, чтобы проверить ввод пользователя перед вызовом `printFormat`/`toBBAN`.** Оба метода форматирования только нормализуют строку — контрольную сумму они не проверяют, поэтому недопустимый IBAN всё равно можно «напечатать» или преобразовать.
- **Вызывайте `useFormatter()` один раз на модуль или компонент и деструктурируйте нужное.** Поскольку оба форматтера — синглтоны, кешировать возвращаемый объект самостоятельно нет смысла, кроме как чтобы избежать шаблонного кода деструктурирования.
- **Для простого форматирования тысяч и десятичных без учёта локали предпочитайте [`Text.numberFormat`](/docs/tools/text/).** `formatterNumber.format` учитывает локаль (через `Intl.NumberFormat`) и всегда округляет нецелые числа ровно до 2 знаков; `Text.numberFormat` позволяет явно выбрать число знаков и разделители, что соответствует серверному форматированию, используемому в других местах полезной нагрузки REST Битрикс24.
- **`addSpecification` существует в основном для внутреннего использования.** `useFormatter()` уже регистрирует каждую поддерживаемую страну при каждом вызове; сама `IbanSpecification` не экспортируется из `@bitrix24/b24jssdk`, поэтому расширение списка стран из кода приложения сегодня не является поддерживаемым публичным сценарием.
