`AjaxResult<T>`{lang="ts-type"} расширяет [`Result<Payload<T>>`{lang="ts-type"}](/docs/tools/core-result/) и является типом, которым завершается каждый `actions.v{2,3}.call.make()`. По сравнению с обычным `Result` он:

- принимает сырой ответ REST (`answer`), исходный запрос (`query`) и HTTP-статус и замораживает их — `setData()` выбрасывает исключение;
- декодирует полезную нагрузку ошибок Битрикс24 в экземпляры [`AjaxError`{lang="ts-type"}](https://github.com/bx-shef/b24-js-sdk/blob/main/packages/jssdk/src/core/http/ajax-error.ts), которые хранятся под ключом `'base-error'`;
- предоставляет члены постраничной загрузки только для `restApi:v2`: чтение конверта (`isMore`, `hasMore`, `getTotal`) и пару для ручной загрузки страниц (`getNext`, `fetchNext`);
- предоставляет HTTP-статус (`getStatus`) и исходный запрос (`getQuery`).

## Чтение данных

```ts-type
getData(): undefined | SuccessPayload<T>
```

Возвращает `undefined`{lang="ts-type"}, если результат неуспешен. При успехе возвращает замороженный объект `{ result, time }`{lang="ts-type"} — и только эти два поля. Поля конверта `next` и `total`, существующие только в `restApi:v2`, **не** передаются; читайте их через [`isMore()`](#ismore) и [`getTotal()`](#gettotal) или доверьте постраничную загрузку `callList`{lang="ts-type"} / `fetchList`{lang="ts-type"}.

`time` необязателен: ответ не всегда его содержит, а SDK его не выдумывает — см. [`PayloadTime`](/docs/tools/types-payloads).

Используйте `T`, чтобы типизировать вложенный `result`:

```ts
const response = await $b24.actions.v2.call.make<{ id: number, title: string }[]>({
  method: 'crm.item.list',
  params: { entityTypeId: 4, select: ['id', 'title'] },
  requestId: 'list-companies'
})

if (!response.isSuccess) {
  throw new Error(response.getErrorMessages().join('; '))
}

const data = response.getData()!     // { result: { id, title }[], time?: PayloadTime }
```

::note
**Тело, которое не является конвертом, оборачивается.** Если в ответе вообще нет ключа `result`, всё тело становится `result`, а не отбрасывается. Так отвечает `rest.documentation.openapi` — документ OpenAPI на верхнем уровне, поэтому `getData()!.result`{lang="ts-type"} — это и есть документ, а `time`{lang="ts-type"} равен `undefined`{lang="ts-type"}. См. [Обнаружение методов v3](/docs/actions/discovering-v3-methods).
::

## Постраничная загрузка

::caution
**Всё в этом разделе читает поля конверта `restApi:v2` — `next` и `total`, — которые `restApi:v3` не отправляет.**

**Ни один из них не объявлен устаревшим.** Ранее планировалось удалить все пять в `3.0.0`, но от этого отказались — см. [заметки о миграции](/docs/getting-started/migration/v3/#вспомогательные-методы-постраничного-обхода-ajaxresult-всё-же-не-удалены). Под v3 они ведут себя иначе:

- `getNext` / `fetchNext` **выбрасывают** `SdkError({ code: 'JSSDK_CORE_METHOD_NOT_SUPPORT_IN_API_V3' })`{lang="ts-type"}. Это сделано намеренно: возврат `false` нельзя было бы отличить от «последней страницы». Под v3 используйте [`actions.v3.fetchList.make`](/docs/actions/fetch-list/).
- `isMore` / `hasMore` / `getTotal` **не выбрасывают исключений** — они возвращают `false`{lang="ts-type"} / `0`{lang="ts-type"}, потому что поля нет. Это не то же самое, что «записей больше нет» или «записей не найдено», поэтому под v3 не стройте на них ветвление.

Для нового кода по-прежнему рекомендуются списочные помощники: они скрывают учёт смещения и работают в обеих версиях протокола.
::

### `isMore` / `hasMore`

```ts-type
isMore(): boolean
hasMore(): boolean   // синоним
```

`true`, если успешная полезная нагрузка содержит **числовое** `next` — `next: 0`{lang="ts-type"} является настоящим смещением и учитывается, строка — нет. Для неуспешных результатов всегда `false`{lang="ts-type"}, а под `restApi:v3`, который не отправляет `next`, — тоже всегда `false`{lang="ts-type"}.

Естественная пара к нему — `getNext` ниже, который также работает только в `restApi:v2`. Под `restApi:v3` не применимы оба, поэтому `isMore()` там вообще не примитив постраничной загрузки — управляйте обходом через `callList` / `fetchList`.

### `getNext`

```ts-type
getNext(http: TypeHttp): Promise<AjaxResult<T> | false>
```

Повторно выполняет исходный метод с `params.start = next`{lang="ts-type"} и возвращает новый `AjaxResult<T>`{lang="ts-type"}. Возвращает `false`{lang="ts-type"}, если следующей страницы нет или текущий результат неуспешен.

### `fetchNext`

```ts-type
fetchNext(http: TypeHttp): Promise<AjaxResult<T> | null>
```

То же, что `getNext`, но вместо `false`{lang="ts-type"} возвращает `null`{lang="ts-type"}.

### `getTotal` / `getStatus` / `getQuery`

```ts-type
getTotal(): number
getStatus(): number
getQuery(): Readonly<AjaxQuery>
```

`getTotal` сообщает `total` из конверта `restApi:v2` и возвращает `0`{lang="ts-type"} для неуспешных результатов — и для любого ответа `restApi:v3`, который `total` не отправляет. Это единственный способ получить число записей в `restApi:v2`: списочные помощники обходят данные, не раскрывая его, [`SuccessPayload`{lang="ts-type"}](/docs/tools/types-payloads/) намеренно его не содержит, а `actions.v3.aggregate.make` (`count` / `countDistinct`) работает только в `restApi:v3` и помечен `@experimental` — ни один поставляемый модуль пока не публикует действие `*.aggregate` ни на одном проверенном портале. `AjaxQuery`{lang="ts-type"} фиксирует `{ method, params, requestId }`; возвращаемый объект и его `params` стабильны — вызов `getNext()` их не изменяет.

## Обработка ошибок

Когда сырой ответ содержит поле `{ error: ... }`, `AjaxResult`{lang="ts-type"} преобразует его в [`AjaxError`{lang="ts-type"}](https://github.com/bx-shef/b24-js-sdk/blob/main/packages/jssdk/src/core/http/ajax-error.ts) (подкласс `SdkError`{lang="ts-type"}) с ключом `'base-error'` в унаследованной карте `errors`. Обрабатываются формы ошибок и v2, и v3. Массив `validation[]` из v3 включается в сообщение **и** остаётся нетронутым в [`AjaxError.validation`](/docs/actions/errors/#какое-поле-не-прошло-проверку-ajaxerrorvalidation) — именно там находится имя поля, не прошедшего проверку: одно сообщение его не содержит (#423).

```ts
import { AjaxError } from '@bxshefby/b24jssdk'

const response = await $b24.actions.v2.call.make({ method: 'profile', requestId: 'p' })
if (!response.isSuccess) {
  for (const error of response.getErrors()) {
    if (error instanceof AjaxError) {
      console.error(error.code, error.requestInfo?.method)
    }
  }
}
```

## `setData` отключён

```ts-type
setData(): never
```

Всегда выбрасывает `ReferenceError('AjaxResult does not allow data modification')`{lang="ts-type"}. Когда нужна агрегация, используйте помощники более высокого уровня (`callList`, `fetchList`, `batch`).
