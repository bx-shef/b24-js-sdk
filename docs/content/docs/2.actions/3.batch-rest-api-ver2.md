## Обзор

Используйте `BatchV2.make()`{lang="ts-type"}, чтобы выполнить до 50 команд REST API в одном запросе. Это особенно полезно, когда нужно получить или обновить большой объём данных, сократив число сетевых запросов и соблюдая ограничения REST API.

```ts
// Basic usage
import { EnumCrmEntityTypeId } from '@bitrix24/b24jssdk'

const response = await $b24.actions.v2.batch.make({
  calls: [
    ['crm.item.get', { entityTypeId: EnumCrmEntityTypeId.contact, id: 1 }],
    ['crm.item.get', { entityTypeId: EnumCrmEntityTypeId.contact, id: 2 }]
  ],
  options: {
    isHaltOnError: true,
    returnAjaxResult: true,
    requestId: 'unique-request-id'
  }
})
```

## Сигнатура метода

```ts-type
make<T = unknown>(
  options: ActionBatchV2
): Promise<CallBatchResult<T>>
```

### Параметры

Объект `options` содержит следующие свойства:

| Параметр | Тип | Обязательный | Описание |
|----|----|----|----|
| **`calls`** | `BatchCommandsArrayUniversal \| BatchCommandsObjectUniversal \| BatchNamedCommandsUniversal`{lang="ts-type"} | Да | Команды, которые нужно выполнить в пакете. Поддерживается несколько [форматов](#форматы-команд-optionscalls). |
| **`options`** | `IB24BatchOptions`{lang="ts-type"} | Нет | [Дополнительные опции](#параметры-пакетного-запроса-optionsoptions) выполнения пакетного запроса. |

### Форматы команд (`options.calls`)

#### 1. Массив кортежей (`BatchCommandsArrayUniversal`)
// @check-ignore: partial snippet — calls array literal, not a valid statement
```ts
calls: [
  ['method1', params1],
  ['method2', params2],
  // ...
]
```

#### 2. Массив объектов (`BatchCommandsObjectUniversal`)
// @check-ignore: partial snippet — object array literal, not a valid statement
```ts
calls: [
  { method: 'method1', params: params1 },
  { method: 'method2', params: params2 },
  // ...
]
```

#### 3. Объект с именованными командами (`BatchNamedCommandsUniversal`)
```ts-type
calls: {
  command1: { method: 'method1', params: params1 },
  command2: ['method2', params2],
  // ...
}
```

### Параметры пакетного запроса (`options.options`)

| Опция | Тип | По умолчанию | Описание |
|----|----|----|----|
| **`isHaltOnError`** | `boolean`{lang="ts-type"} | `true` | Останавливать ли выполнение на первой ошибке. |
| **`returnAjaxResult`** | `boolean`{lang="ts-type"} | `false` | Возвращать ли объект `AjaxResult` вместо данных. |
| **`requestId`** | `string`{lang="ts-type"} | — | Уникальный идентификатор запроса для отслеживания и отладки — передаётся в query-параметре `bx24_request_id`. Он ничего не дедуплицирует; для этого есть `idempotencyKey` (restApi:v3). |


::warning
Эти опции указываются **внутри** `options`. Если передать их свойствами верхнего уровня аргумента, они **не применяются**: TypeScript отклоняет такой литерал, а вызывающий код, которого компилятор не видит (обычный JavaScript или литерал, расширенный через переменную), получает предупреждение в журнале с названием флага и местом, куда его нужно поместить. До этого (#426) всё происходило молча, и хуже всего приводил к последствиям `returnAjaxResult`, потерянный таким образом: `isSuccess` у обычных данных равен `undefined`, поэтому пакет, в котором все команды выполнились успешно, выглядит как пакет, где все команды завершились ошибкой.
::

### Возвращаемое значение

Форма результата выбирается по аргументам, и перегрузки определяют, что вы получите, —
без приведения типов и ручного сужения:

| `calls` | `options.returnAjaxResult` | разрешается в |
| --- | --- | --- |
| именованные команды (запись) | отсутствует / `false` | `Result<Record<string, T>>`{lang="ts-type"} — данные по имени команды |
| именованные команды (запись) | `true` | `Result<Record<string, AjaxResult<T>>>`{lang="ts-type"} |
| массив команд (кортежи **или** объекты) | отсутствует / `false` | `Result<T[]>`{lang="ts-type"} — данные по позиции |
| массив команд (кортежи **или** объекты) | `true` | `Result<AjaxResult<T>[]>`{lang="ts-type"} |

`T` во всех строках — это данные **одной команды**, а не коллекции.

::warning
**Аргументы команды указываются в `params`.** Если записать их под `query`, их
не прочитает никто: команда v2 уходит по сети как `method?<querystring>`, собранная
из `params`, то есть отправляется вообще без аргументов, а портал отвечает HTTP
200 со значениями метода по умолчанию.

Измерено на `user.get` с `filter: { ACTIVE: 'N' }` на портале, где единственный
пользователь активен: с `params` портал вернул **0 строк** — фильтр сработал, — а тот же
запрос с `query` вернул **1 строку**: активного пользователя, которого фильтр должен был исключить.
Это неверный ответ, а не сбой.

`query` — это написание `restApi:v3` в запросе, поэтому именно его выбирает вызывающий код;
в v2 это просто ключ, который парсер не читает.

TypeScript отклоняет его в свежем литерале объекта. Но он не видит тот же литерал,
сначала присвоенный переменной, команды, построенные из объекта конфигурации, `JSON.parse`
или обычный JavaScript, поэтому SDK предупреждает и во время выполнения: одна строка
на пакетный запрос с названием проигнорированных ключей и команд, которые их несли.
Предупреждение выводится, только когда аргументы действительно потеряны, — у команды без
`params` или у команды с `query`. Ваши собственные `id` или `label` рядом с заполненным
`params` не затрагиваются.
::

::note
Массив *объектов* команд (`[{ method, params }]`) отвечает **по индексу**, как и
форма с кортежами. По имени отвечает форма записи (`{ name: { method, params } }`) — выбор делается по
контейнеру, а не по тому, как выглядят элементы.
::

::caution
Когда `returnAjaxResult` — это `boolean`, который компилятор не может прочитать как литерал
(переменная, а не `true` или `false`, записанные на месте), ни одна перегрузка не может
решить за вас, и вызов разрешается в объединение
`CallBatchResult<T>`{lang="ts-type"}. Это честно, но не удобно: сузьте
тип самостоятельно или передавайте флаг литералом.
::

## Данные элемента результата

Каждый `result` отдельной команды возвращается ровно так, как его доставил REST API,
включая `null`, когда нижележащий метод законно не возвращает данных
(например, `im.chat.get`, вызванный с `ENTITY_TYPE`, который не соответствует
ни одному чату).

```ts
const response = await $b24.actions.v2.batch.make<{ ID: number } | null>({
  calls: {
    chatGet: {
      method: 'im.chat.get',
      params: { ENTITY_TYPE: 'UNKNOWN', ENTITY_ID: 'UNKNOWN' }
    }
  },
  options: { returnAjaxResult: true, requestId: 'chat-get' }
})

// No cast and no `@check-ignore`: named commands plus `returnAjaxResult: true`
// resolve to a record of `AjaxResult`, and the overloads read that off the
// arguments (#518).
const chatGet = response.getData()!.chatGet!
if (chatGet.getData()?.result === null) {
  // method returned null — no chat matched
} else {
  console.log(chatGet.getData()?.result.ID)
}
```

::note
До v1.1.1 результат `null` приводился к `{}`, что ломало защитные проверки типов для nullable-значений
на стороне вызывающего кода (см. [issue #23](https://github.com/bitrix24/b24jssdk/issues/23)).
Если типизируете generic для методов, которые могут вернуть `null`, объявляйте его как
`T | null`{lang="ts-type"}.
::

## Обработка ошибок

Всегда проверяйте результат через `isSuccess` и обрабатывайте ошибки:

// @check-ignore: top-level return in error-handling illustration
```ts
const response = await $b24.actions.v2.batch.make({
  calls: [
    { method: 'crm.item.get', params: { entityTypeId: EnumCrmEntityTypeId.contact, id: 1 } },
    { method: 'crm.item.get', params: { entityTypeId: EnumCrmEntityTypeId.contact, id: 2 } }
  ],
  options: {
    isHaltOnError: true,
    returnAjaxResult: true,
    requestId: 'unique-request-id'
  }
})

if (!response.isSuccess) {
  // Handling error
  console.error(new Error(`Error: ${response.getErrorMessages().join('; ')}`))
  return
}

// Working with a successful result
const data = response.getData()
```

Проверка `isSuccess` охватывает **два** разных сбоя:

- **Ошибки отдельных команд** — конверт пакета выполнен успешно, но отдельные команды завершились ошибкой. Проверьте каждый `AjaxResult` в `getData()` или используйте `getErrorsByKey()`, чтобы увидеть, какая команда не выполнилась.
- **Ошибки уровня конверта (мягкие)** — весь пакет завершается ошибкой до возврата результатов команд, например из-за серверного кода валидации (`BITRIX_REST_V3_EXCEPTION_VALIDATION_*`). Тогда внешний `Result` имеет `isSuccess === false`, ошибки находятся в `getErrorMessages()` / `getErrors()`, а `getData().result` пуст. Если этот код относится к валидации,
`AjaxError` также называет поле, которое не прошло проверку, — см.
[Какое поле не прошло проверку](/docs/actions/errors/#какое-поле-не-прошло-проверку-ajaxerrorvalidation).

Одна проверка `if (!response.isSuccess)` обрабатывает оба случая.

## Альтернативы и рекомендации

* **Для последовательных запросов**: используйте [`Call`](/docs/actions/call-rest-api-ver2/) для одиночных вызовов.
* **Для работы со списками**: используйте [`CallList`](/docs/actions/call-list-rest-api-ver2/) для получения больших объёмов данных.
* **Для пошаговой обработки**: используйте [`FetchList`](/docs/actions/fetch-list-rest-api-ver2/) для обработки данных по мере поступления.
* **Чтобы выполнить больше команд (более 50)**: используйте [`BatchByChunk`](/docs/actions/batch-by-chunk-rest-api-ver2/), который автоматически разбивает команды на порции по 50.
* **На стороне клиента (в браузере):** используйте встроенный объект [`B24Frame`](/docs/getting-started/installation/vue/#инициализация).
