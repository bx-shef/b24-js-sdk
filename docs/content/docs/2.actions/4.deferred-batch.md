## Обзор

`$b24.actions.v3.deferredBatch` оборачивает методы портала `rest.deferredbatch.*`.
Отложенный пакет — это **фоновое задание**:

1. `rest.deferredbatch.add` принимает **все** команды одним вызовом — тысячи
   команд, намного больше 50 у синхронного [`batch`](/docs/actions/batch/).
   Измерено: 5000 команд `tasks.task.get` в одном задании выполнились менее чем за 5 секунд
   ([#570](https://github.com/bitrix24/b24jssdk/issues/570#issuecomment-5844466488)).
2. Портал выполняет их в фоне. Статус задания проходит
   `pending` → `processing` → `done` или завершается `error` (наблюдались все четыре).
3. Результаты сохраняются в виде JSON-файла, сжатого gzip. SDK скачивает его
   и декодирует в строки — по одной строке на команду, в порядке команд.

В отличие от [`batchByChunk`](/docs/actions/batch-by-chunk/),
который отправляет один запрос на каждые 50 команд, отложенный пакет — это один запрос на
запуск, а затем проверки статуса до завершения. Как портал учитывает фоновое
задание в лимите операционного времени, не измерялось.

::warning
Отложенные пакеты зависят от **тарифа** портала. На тарифе без них каждый
вызов отвечает `FEATURE_NOT_AVAILABLE_ON_CURRENT_PLAN` (наблюдалось на таком портале,
[#570](https://github.com/bitrix24/b24jssdk/issues/570)). Какая область доступа нужна
этим методам, не измерялось.
::

::warning
**Правила, измеренные на портале** ([#570](https://github.com/bitrix24/b24jssdk/issues/570#issuecomment-5844638165)):

* **Только методы v3.** Метод v2 (`user.current`) или неизвестный метод отклоняется
  на `add` с `INVALID_METHOD`; задание не создаётся.
* **Всё или ничего.** Если одна команда завершается ошибкой (достаточно `get` записи, которой
  не существует), всё задание завершается `error` (`errorMessage: "Result does
  not exists"`), и **файла результата нет** — даже для команд, которые
  выполнились. Стройте команды, которые не могут упасть на данных: страницы списков, а не
  `get` на каждый id.
* **Длительность зависит от метода, а не только от числа команд.** 5000 лёгких `get`
  выполнились за секунды; 500 `rest.scope.list` всё ещё выполнялись через 15
  минут. Задавайте `timeout` под вашу нагрузку.
* **Выполняющееся задание нельзя удалить** — портал отвечает `BATCH_PROCESSING`.
  Удаляйте его, когда оно перейдёт в `done` или `error`.
::

::note
**Измерено через вебхук.** В браузере (`B24Frame`) файл результата можно
прочитать: портал отдаёт его с `Access-Control-Allow-Origin: *` (измерено, [#570](https://github.com/bitrix24/b24jssdk/issues/570#issuecomment-5844778591));
полный прогон из фрейма
не выполнялся. `idempotencyKey` недоступен в браузере — см.
[Idempotency-Key](/docs/actions/call/#idempotency-key).
::

Есть два способа использования:

| Что вы хотите | Что использовать |
| --- | --- |
| Выполнить команды и получить строки с обратным вызовом о прогрессе | [`make()`](#сигнатура-метода) |
| Запустить задание сейчас и забрать результат позже — другим запросом, воркером очереди, опросом из вашего интерфейса | [отдельные шаги](#пошагово) |

## Сигнатура метода

```ts-type
make<T = unknown>(options: ActionDeferredBatchV3): Promise<Result<T[]>>

add(options: ActionDeferredBatchAddV3): Promise<Result<DeferredBatchJob>>
get(id: number): Promise<Result<DeferredBatchJob>>
waitFor(id: number, options?: ActionDeferredBatchWaitV3): Promise<Result<DeferredBatchJob>>
download<T = unknown>(id: number): Promise<Result<T[]>>
delete(id: number): Promise<Result<boolean>>
list(): Promise<Result<DeferredBatchJob[]>>
getDownloadUrl(id: number): Promise<Result<string>>
decode(bytes: ArrayBuffer | Uint8Array): Promise<unknown[]>
```

### Всё за один вызов: `make()`

```ts
// const $b24 = ...
import type { BatchCommandsArrayUniversal, DeferredBatchJob } from '@bxshefby/b24jssdk'

interface TaskPage { items: Array<{ id: number, title: string }> }

// 200 pages of 50 tasks. List pages, not a `get` per id: one failing command
// fails the whole job, while a page past the end is just empty (measured).
const calls: BatchCommandsArrayUniversal = Array.from({ length: 200 }, (_, i) => [
  'tasks.task.list',
  { select: ['id', 'title'], order: { id: 'ASC' }, pagination: { page: i + 1, limit: 50 } }
])

const response = await $b24.actions.v3.deferredBatch.make<TaskPage>({
  calls,
  // Called on every status change, e.g. pending → done.
  onStatus: (job: DeferredBatchJob) => console.log(`job #${job.id}: ${job.status}`)
})

if (!response.isSuccess) {
  throw new Error(response.getErrorMessages().join('; '))
}

const pages = response.getData()! // one row per command, in order
const titles = pages.flatMap(page => page.items.map(task => task.title))
console.log(`${titles.length} tasks in ${pages.length} pages`)
```

`make()` добавляет задание, ждёт его завершения, скачивает и декодирует файл
результата и удаляет задание. То, что отвечает портал, никогда не заставляет его выбрасывать исключение: проверяйте
`isSuccess`. Исключение выбрасывается только для неверно сформированных `calls`, до отправки чего-либо.

#### Опции

| Опция | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `calls` | `DeferredBatchCalls`{lang="ts-type"} | — | Команды: `[['method', params], …]`, `[{ method, params }, …]` или оба вида вперемешку. Именованные команды не поддерживаются — результат является массивом. |
| `onStatus` | `(job: DeferredBatchJob) => void`{lang="ts-type"} | — | Вызывается при смене статуса, включая первый статус. Исключение в нём (или отклонение, если он `async`) записывается в журнал и игнорируется. |
| `pollInterval` | `number`{lang="ts-type"} | `2000` | Миллисекунды между проверками статуса. Не меньше `250`. |
| `timeout` | `number`{lang="ts-type"} | `600000` | Миллисекунды ожидания `done` / `error`. |
| `signal` | `AbortSignal`{lang="ts-type"} | — | Прекращает ожидание. |
| `deleteAfter` | `boolean`{lang="ts-type"} | `true` | Удалять задание и его файл после чтения. |
| `idempotencyKey` | `string`{lang="ts-type"} | — | Отправляется вместе с `add`. Используйте один ключ на запуск: по контракту идемпотентности портала (для отложенных пакетов не измерялся) повтор прерванного `make()` с тем же ключом не запустит второе задание, а ключ, повторно использованный после завершённого `make()`, удалившего своё задание, воспроизвёл бы идентификатор уже не существующего задания. См. [Idempotency-Key](/docs/actions/call/#idempotency-key). |
| `requestId` | `string`{lang="ts-type"} | — | Отправляется как `bx24_request_id` вместе с `add`. |

## Примеры

### Прогресс в интерфейсе и отмена

```ts
// const $b24 = ...
declare const calls: [string, Record<string, unknown>][]
declare function showStatus(text: string): void

const controller = new AbortController()
// e.g. wired to a "Cancel" button: cancelButton.onclick = () => controller.abort()

const response = await $b24.actions.v3.deferredBatch.make({
  calls,
  pollInterval: 3_000,
  timeout: 30 * 60_000,
  signal: controller.signal,
  onStatus: job => showStatus(job.status === 'done' ? 'Downloading results…' : `Status: ${job.status}`)
})

if (!response.isSuccess) {
  // JSSDK_DEFERRED_BATCH_ABORTED, _TIMEOUT or _FAILED — see "Errors" below.
  showStatus(response.getErrorMessages().join('; '))
}
```

Прерывание или тайм-аут останавливают **ожидание**, а не задание: оно продолжает выполняться
на портале, и его можно забрать позже шагами ниже. `Result` метода `make()`
не содержит идентификатор задания; его передаёт `onStatus` — он вызывается с заданием, как только
оно впервые прочитано, — поэтому сохраните идентификатор оттуда, если, возможно, захотите забрать результат.

### Пошагово

Каждый шаг — один метод и возвращает `Result`:

| Метод | Метод портала | Возвращает |
| --- | --- | --- |
| `add({ calls, idempotencyKey?, requestId? })` | `rest.deferredbatch.add` | `Result<DeferredBatchJob>`{lang="ts-type"} — новое задание, обычно `pending` |
| `get(id)` | `rest.deferredbatch.get` | `Result<DeferredBatchJob>`{lang="ts-type"} |
| `waitFor(id, { pollInterval?, timeout?, signal?, onStatus? })` | `rest.deferredbatch.get`, повторно | `Result<DeferredBatchJob>`{lang="ts-type"} — задание в итоговом состоянии |
| `download<T>(id)` | `rest.deferredbatch.downloadresult` + файл | `Result<T[]>`{lang="ts-type"} — декодированные строки |
| `delete(id)` | `rest.deferredbatch.delete` | `Result<boolean>`{lang="ts-type"} — отклоняется, пока задание `processing` |
| `list()` | `rest.deferredbatch.list` | `Result<DeferredBatchJob[]>`{lang="ts-type"} |
| `getDownloadUrl(id)` | `rest.deferredbatch.downloadresult` | `Result<string>`{lang="ts-type"} — ссылка на файл (это учётные данные, см. ниже) |
| `decode(bytes)` | — | `Promise<unknown[]>`{lang="ts-type"} — gunzip + JSON байтов файла |

#### Запустить сейчас, забрать позже

```ts
// const $b24 = ...
declare const calls: [string, Record<string, unknown>][]
declare function saveJobId(id: number): Promise<void>
declare function loadJobId(): Promise<number>

// Request 1: start the job and remember its id.
const added = await $b24.actions.v3.deferredBatch.add({ calls })
if (!added.isSuccess) {
  throw new Error(added.getErrorMessages().join('; '))
}
await saveJobId(added.getData()!.id)

// Request 2, later: is it ready?
const jobId = await loadJobId()
const job = (await $b24.actions.v3.deferredBatch.get(jobId)).getData()

if (job?.status === 'done') {
  const rows = await $b24.actions.v3.deferredBatch.download(jobId)
  console.log(`${rows.getData()?.length ?? 0} rows`)
  await $b24.actions.v3.deferredBatch.delete(jobId)
} else if (job?.status === 'error') {
  console.error(job.errorMessage)
}
```

#### Объект задания

```ts-type
interface DeferredBatchJob {
  id: number
  status: 'pending' | 'processing' | 'done' | 'error'
  commands?: Array<{ method: string, query: Record<string, unknown> }>
  createdAt?: string
  updatedAt?: string
  resultFileId?: number | null // set once `done`
  errorMessage?: string | null // set when `error`
}
```

## Строки результата

Строка — это то, что вернула соответствующая команда, в порядке команд, в той же форме, что и
одна запись результата синхронного пакета v3: `{ item }` для `get`, `{ items }` для
`list` и так далее. Строка не содержит блока `time`. Строк с ошибками нет:
у задания с упавшей командой файла результата нет вообще (см. правила выше).

Весь файл удерживается в памяти во время декодирования. Строки, каждая из которых содержит
целую страницу списка, быстро накапливаются; очень большие выгрузки делите на несколько заданий.

`download()` / `make()` декодируют файл за вас. Если вы скачали его иначе,
`decode()` делает то же самое: распаковывает байты (файл имеет тип
`application/gzip`) и разбирает JSON-массив. Байты, уже распакованные — например прокси,
который их разжал, — разбираются как есть. Для декодирования используется стандартный
`DecompressionStream`, доступный в Node.js 18+ и современных браузерах.

## Безопасность: ссылка на скачивание — это учётные данные

`rest.deferredbatch.downloadresult` отвечает абсолютным URL, который несёт
учётные данные вызывающего: измерено — секрет вебхука в пути; по коду
портала — токен доступа для OAuth-приложения. SDK сам скачивает файл,
не включает ссылку в создаваемые им ошибки, отказывается следовать по редиректам с ней, а его журнал
ответа `downloadresult` маскирует секрет и токен. `getDownloadUrl()` отдаёт ссылку вам: обращайтесь с ней так же, как
с самим URL вебхука. Удаление задания делает ссылку нерабочей.

## Обработка ошибок

| Код | Когда |
| --- | --- |
| `JSSDK_DEFERRED_BATCH_FAILED` | Задание завершилось со статусом `error` — достаточно одной упавшей команды. `make()` записывает в журнал `errorMessage` портала и удаляет задание (если не задано `deleteAfter: false`); `waitFor()` возвращает задание как данные вместе с его `errorMessage`. В сообщении указан идентификатор задания. |
| `JSSDK_DEFERRED_BATCH_TIMEOUT` | Итоговый статус не получен за `timeout`. Задание продолжает выполняться и пока не может быть удалено; в сообщении указан его идентификатор, чтобы забрать результат позже. |
| `JSSDK_DEFERRED_BATCH_ABORTED` | `signal` был прерван. Уже добавленное задание продолжает выполняться; в сообщении указан его идентификатор. |
| `JSSDK_DEFERRED_BATCH_DOWNLOAD_FAILED` | Не удалось скачать файл результата; в сообщении указан HTTP-статус. |
| `JSSDK_DEFERRED_BATCH_DECODE_FAILED` | Файл не является корректным gzip или не является JSON-массивом. |
| `JSSDK_DEFERRED_BATCH_GZIP_UNSUPPORTED` | В среде выполнения нет `DecompressionStream`. |
| `JSSDK_DEFERRED_BATCH_EMPTY` | `calls` пуст — выбрасывается до отправки чего-либо. |
| `JSSDK_DEFERRED_BATCH_UNEXPECTED_RESPONSE` | Портал ответил без данных, которых ожидает шаг (например, `add` без `item`). |
| `JSSDK_INTERACTION_BATCH_ROW_FAIL` | Команда в `calls` не является ни кортежем, ни объектом `{ method, params }` — выбрасывается до отправки чего-либо. |
| `FEATURE_NOT_AVAILABLE_ON_CURRENT_PLAN` | На тарифе портала нет отложенных пакетов. |
| `INVALID_METHOD` | В `add` указан метод v2 или неизвестный метод; отложенный пакет принимает только методы v3. Задание не создано. |
| `BATCH_PROCESSING` | `delete` задания, которое всё ещё `processing`. |

## Альтернативы и рекомендации

* **До 50 команд, результат нужен сразу:** синхронный
  [`batch`](/docs/actions/batch/) проще и
  возвращает результат в том же запросе.
* **Больше 50, а на тарифе нет отложенных пакетов:**
  [`batchByChunk`](/docs/actions/batch-by-chunk/)
  выполняет ту же работу одним запросом на 50 команд.
* **Чтение всего списка:** [`fetchList`](/docs/actions/fetch-list/)
  или [`fetchTail`](/docs/actions/fetch-tail/)
  листают его без построения тысяч команд `get`.
* **Записи, которые не должны повторяться:** передайте `idempotencyKey`, один на запуск, чтобы
  повторённый `add` не запускал второе задание (контракт идемпотентности портала;
  для отложенных пакетов не измерялся).
* **Отмена:** `signal` работает как в списочных действиях, но прерывание
  приходит как `JSSDK_DEFERRED_BATCH_ABORTED` в `Result`, а не как выброшенное
  `JSSDK_ACTION_ABORTED`, в соответствии с тем, что `make()` никогда не выбрасывает исключений.
* **Большие файлы результата:** скачивание использует таймаут HTTP-клиента (по умолчанию 30 с),
  а не `timeout`. Увеличьте `getHttpClient(ApiVersion.v3).ajaxClient.defaults.timeout`
  для очень больших заданий.
* **Записи:** «всё или ничего» относится только к *результату* задания. Упавшая
  команда завершает его `error` без файла, но ничто не говорит, что записи,
  выполненные до неё, были отменены, — поэтому для записей предпочитайте команды, которые не могут упасть,
  и проверяйте данные портала после `error`.
