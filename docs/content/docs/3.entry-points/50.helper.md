## Обзор

`B24HelperManager`{lang="ts-type"} выполняет один пакетный REST-запрос (`profile`, `app.info`, `crm.currency.base.get`, `crm.currency.list`, `app.option.get`, `user.option.get`) и отдаёт разобранный результат через специализированные подменеджеры. Он также управляет жизненным циклом [клиента Pull](/docs/working-with-the-rest-api/pull/) — подключение, подписка, запуск, уничтожение.

Обычно вы работаете с `B24HelperManager`{lang="ts-type"} косвенно, через композабл [`useB24Helper`](/docs/working-with-the-rest-api/helper-use-b24-helper/). Прямое создание поддерживается, но нужно редко.

```ts
import { useB24Helper, LoadDataType, initializeB24Frame } from '@bitrix24/b24jssdk'

const { initB24Helper, getB24Helper } = useB24Helper()

const $b24 = await initializeB24Frame()
await initB24Helper($b24, [
  LoadDataType.Profile,
  LoadDataType.App,
  LoadDataType.Currency,
  LoadDataType.AppOptions,
  LoadDataType.UserOptions
])

const helper = getB24Helper()
console.log(helper.profileInfo.data, helper.appInfo.data)
```

## Конструктор

```ts-type
constructor(b24: TypeB24)
```

Принимает любой экземпляр `TypeB24`{lang="ts-type"} — `B24Frame`{lang="ts-type"}, `B24Hook`{lang="ts-type"} или `B24OAuth`{lang="ts-type"}. Помощник **не** вызывает `init()` за вас: к моменту выполнения `loadData()` переданный экземпляр уже должен быть инициализирован.

## Методы

### `loadData`

```ts-type
loadData(
  dataTypes?: LoadDataType[],
  requestId?: string
): Promise<void>
```

Загружает запрошенные наборы данных через `actions.v2.batch.make({ isHaltOnError: true })`. После завершения становятся доступны соответствующие геттеры (`profileInfo`, `appInfo` и другие); до этого они выбрасывают `'B24HelperManager not initialized'`{lang="ts-type"}.

При сбое промис отклоняется. `Error`{lang="ts-type"}, возникший в пакетном вызове, — включая `AjaxError`{lang="ts-type"} и `SdkError`{lang="ts-type"}, — пробрасывается без изменений, поэтому `code` / `status` сохраняются. Оборачивается только выброшенное значение, которое вообще не является `Error`{lang="ts-type"}: оно попадает в `new Error('Failed to load data')`{lang="ts-type"}, а исходное значение прикладывается как [`cause`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/cause), чтобы не потеряться.

`dataTypes` по умолчанию равен `[LoadDataType.App, LoadDataType.Profile]`{lang="ts-type"}.

`requestId` по умолчанию равен `'helper-load-data'`. Переопределите его для удобства трассировки.

#### Перечисление `LoadDataType`

| Значение | Вызываемые REST-методы | Получаемый менеджер |
|----|----|----|
| `App` | `app.info` | [`appInfo`](/docs/working-with-the-rest-api/helper-app-manager/), [`paymentInfo`](/docs/working-with-the-rest-api/helper-payment-manager/), [`licenseInfo`](/docs/working-with-the-rest-api/helper-license-manager/) |
| `Profile` | `profile` | [`profileInfo`](/docs/working-with-the-rest-api/helper-profile-manager/) |
| `Currency` | `crm.currency.base.get` + `crm.currency.list` | [`currency`](/docs/working-with-the-rest-api/helper-currency-manager/) |
| `AppOptions` | `app.option.get` | [`appOptions`](/docs/working-with-the-rest-api/helper-options-manager/) |
| `UserOptions` | `user.option.get` | [`userOptions`](/docs/working-with-the-rest-api/helper-options-manager/) |

### `getLogger` / `setLogger`

```ts-type
getLogger(): LoggerInterface
setLogger(logger: LoggerInterface): void
```

`setLogger` передаёт логгер во все разобранные подменеджеры. По умолчанию — `LoggerFactory.createNullLogger()`{lang="ts-type"}.

### `destroy`

```ts-type
destroy(): void
```

Завершает работу клиента Pull (отписка и отключение). Идемпотентен.

### Связка с клиентом Pull

```ts-type
usePullClient(prefix?: string, userId?: number): B24HelperManager
subscribePullClient(callback: (message: TypePullMessage) => void, moduleId?: string): B24HelperManager
startPullClient(): void
getModuleIdPullClient(): string
```

Порядок важен: `usePullClient()` → `subscribePullClient()` (один или несколько раз) → `startPullClient()`. Полный порядок действий — в разделе [Клиент Pull](/docs/working-with-the-rest-api/pull/). `getModuleIdPullClient()` возвращает `moduleId`, который последним передали в `subscribePullClient`; он предназначен для данных `pull.application.event.add`.

## Геттеры

::caution
Все перечисленные ниже геттеры выбрасывают `'B24HelperManager not initialized'`{lang="ts-type"}, пока не завершится `loadData()`. Кроме того, каждый геттер выбрасывает ошибку, если соответствующий `LoadDataType` не был запрошен.
::

### `isInit`

```ts-type
get isInit(): boolean
```

`true`{lang="ts-type"}, когда `loadData()` успешно завершён.

### `profileInfo` / `appInfo` / `paymentInfo` / `licenseInfo` / `currency` / `appOptions` / `userOptions`

Возвращают разобранный подменеджер. См.:

- [ProfileManager](/docs/working-with-the-rest-api/helper-profile-manager/)
- [AppManager](/docs/working-with-the-rest-api/helper-app-manager/)
- [PaymentManager](/docs/working-with-the-rest-api/helper-payment-manager/)
- [LicenseManager](/docs/working-with-the-rest-api/helper-license-manager/)
- [CurrencyManager](/docs/working-with-the-rest-api/helper-currency-manager/)
- [OptionsManager](/docs/working-with-the-rest-api/helper-options-manager/)

### `forB24Form`

```ts-type
get forB24Form(): TypeB24Form
```

Возвращает плоский объект, пригодный для отправки в [CRM-форму обратной связи](https://github.com/bitrix24/b24sdk-examples/blob/main/js/03-nuxt-frame/pages/feedback.client.vue) Битрикс24. Нужны оба — `LoadDataType.App` и `LoadDataType.Profile`.

| Поле | Тип | Описание |
|----|----|----|
| `app_code` | `string`{lang="ts-type"} | Код приложения в Битрикс24. |
| `app_status` | `string`{lang="ts-type"} | Статус приложения (`F` / `D` / `T` / `P` / `L` / `S`). |
| `payment_expired` | `BoolString`{lang="ts-type"} | `'Y'`, если платный или пробный период закончился, иначе `'N'`. |
| `days` | `number`{lang="ts-type"} | Сколько дней осталось до истечения или прошло с него. |
| `b24_plan` | `string`{lang="ts-type"} | Идентификатор тарифа облака Битрикс24. |
| `c_name` / `c_last_name` | `string`{lang="ts-type"} | Имя и фамилия из профиля. |
| `hostname` | `string`{lang="ts-type"} | Адрес портала (например, `xxx.bitrix24.com`). |

### `hostName`

```ts-type
get hostName(): string
```

Origin портала (`https://xxx.bitrix24.com`). Берётся из `b24.getTargetOrigin()`.

### `isSelfHosted`

```ts-type
get isSelfHosted(): boolean
```

`true`{lang="ts-type"}, если строка лицензии содержит `selfhosted`. Нужен `LoadDataType.App`.

### `primaryKeyIncrementValue`

```ts-type
get primaryKeyIncrementValue(): number
```

Возвращает шаг приращения для полей-идентификаторов: `1`{lang="ts-type"} на портале в собственной инфраструктуре, `2`{lang="ts-type"} в облаке.

### `b24SpecificUrl`

```ts-type
get b24SpecificUrl(): Record<keyof typeof TypeSpecificUrl, string>
```

Возвращает URL административных разделов, которые различаются в облаке и в собственной инфраструктуре:

| Ключ | Облако | Собственная инфраструктура |
|----|----|----|
| `MainSettings` | `/settings/configs/` | `/configs/` |
| `UfList` | `/settings/configs/userfield_list.php` | `/configs/userfield_list.php` |
| `UfPage` | `/settings/configs/userfield.php` | `/configs/userfield.php` |
