## Обзор

SDK для работы с REST API Битрикс24 предоставляет набор инструментов для взаимодействия с API Битрикс24 из приложений на JavaScript/TypeScript.

::rest-api-version-only
#rest-api-ver2
Библиотека поддерживает как REST API версии 2 (процесс отказа от неё начался, но она по-прежнему широко используется), так и новую версию 3 (процесс внедрения начался).
::

## Архитектура SDK

SDK построен на трёх основных классах, которые наследуют общий базовый класс и предоставляют единый интерфейс для работы с REST API:

### Три класса для разных сценариев использования

| Класс | Назначение | Где использовать | Особенности |
|-------|---------|--------------|----------|
| `B24Frame`{lang="ts-type"} | Работа из приложений, встроенных в интерфейс Битрикс24 | Клиентская сторона (браузер) | Автоматически доступен в iframe приложения Битрикс24, использует токен текущего пользователя |
| `B24Hook`{lang="ts-type"} | Работа из самостоятельных серверных приложений через вебхук | Серверная сторона | Использует постоянный токен вебхука, **нельзя использовать в браузере** |
| `B24OAuth`{lang="ts-type"} | Работа из самостоятельных серверных приложений через OAuth 2.0 | Серверная сторона | Использует токен OAuth с возможностью обновления, **нельзя использовать в браузере** |

### Общий интерфейс

Все три класса наследуют общий базовый класс и предоставляют один и тот же набор методов.

Все три класса реализуют интерфейс [`TypeB24`](https://github.com/bx-shef/b24-js-sdk/blob/main/packages/jssdk/src/types/b24.ts), который задаёт единый набор возможностей:

```ts-type
type TypeB24 = {
  readonly isInit: boolean
  init(): Promise<void>
  destroy(): void

  getLogger(): LoggerInterface
  setLogger(logger: LoggerInterface): void

  get auth(): AuthActions

  // REST API (v2 / v3) — call, callList, fetchList, batch, batchByChunk
  get actions(): ActionsManager

  // Вспомогательные утилиты (healthCheck, ping)
  get tools(): ToolsManager

  setRestrictionManagerParams(params: RestrictionParams): Promise<void>

  getTargetOrigin(): string
  getTargetOriginWithPath(): Map<ApiVersion, string>

  getHttpClient(version: ApiVersion): TypeHttp
  setHttpClient(version: ApiVersion, client: TypeHttp): void
}
```

К методам REST можно обратиться через `actions.v2.*` и `actions.v3.*`:

```ts-type
// $b24 — экземпляр B24Frame | B24Hook | B24OAuth

await $b24.actions.v2.call.make(options)         // Promise<AjaxResult>
await $b24.actions.v2.callList.make(options)     // Promise<Result<T[]>>
$b24.actions.v2.fetchList.make(options)          // AsyncGenerator<T[]>
await $b24.actions.v2.batch.make(options)        // Promise<CallBatchResult>
await $b24.actions.v2.batchByChunk.make(options) // Promise<Result<T[]>>

// v3 устроен так же и добавляет нативный обход по ключу для тех немногих
// методов, у которых есть эндпоинт `*.tail`
await $b24.actions.v3.call.make(options)
await $b24.actions.v3.callTail.make(options)     // Promise<Result<T[]>>
$b24.actions.v3.fetchTail.make(options)          // AsyncGenerator<T[]>
// ...

await $b24.tools.healthCheck.make({ requestId })  // Promise<boolean>
await $b24.tools.ping.make({ requestId })         // Promise<number>
```

## Ключевые возможности

### Основные методы API

- **`Call`** — базовый метод для вызова любых методов REST API
- **`CallList`** — автоматическое получение всех данных из списочных методов с постраничной выборкой
- **`FetchList`** — пошаговая обработка больших объёмов данных через AsyncGenerator
- **`Batch`** — выполнение до 50 команд в одном запросе
- **`BatchByChunk`** — автоматическое разбиение больших наборов команд на пакеты
- **[`DeferredBatch`](/docs/actions/deferred-batch/)** — тысячи команд как одно фоновое задание на портале, с обратным вызовом о статусе и декодированными строками (`restApi:v3`)

### Вспомогательные инструменты

- **`HealthCheck`** — проверка доступности REST API
- **`Ping`** — измерение времени ответа API

## Общие методы (доступны во всех классах)

### Архитектура методов

| Метод | Возвращаемое значение | Память | Использование | Подходит для |
|-------|----------------------|--------|---------------|-------------------|
| `Call`{lang="ts-type"} | `Promise<AjaxResult>`{lang="ts-type"} | Минимум | Одиночные вызовы | Получение отдельных элементов, вызов методов без постраничной выборки |
| `CallList`{lang="ts-type"} | `Promise<Result<T[]>>`{lang="ts-type"} | Все данные в памяти | `await response.getData()` | Небольшие и средние объёмы данных, когда все данные нужны сразу |
| `FetchList`{lang="ts-type"} | `AsyncGenerator<T[]>`{lang="ts-type"} | Обработка по частям | `for await (const chunk of generator)` | Большие объёмы данных, потоковая обработка, ограниченная память |
| `Batch`{lang="ts-type"} | `Promise<CallBatchResult>`{lang="ts-type"} | Зависит от объёма | Пакетные операции до 50 команд | Массовые операции, оптимизация сетевых запросов |

### Неизвестная опция — это ошибка, а не пожатие плечами

Тип опций каждого действия перечисляет ровно те ключи, которые оно читает. Ключ,
которого нет в списке, — опечатка вроде `customKeyForResults` или опция, записанная на уровень
выше нужного, — это ошибка TypeScript, а не то, что молча отбрасывается.

`batch.make({ calls, isHaltOnError: false })` — как раз такая форма: флаг
относится к `options`, а на верхнем уровне его не читал никто. Правильная запись:

```ts
await $b24.actions.v2.batch.make({
  calls: { now: ['server.time', {}] },
  options: { isHaltOnError: false }
})
```

До #426 типы опций содержали index signature, поэтому компилировался **любой** ключ верхнего уровня,
а ключи не на своём месте ничего не делали. Пакетные действия дополнительно выводят
предупреждение во время выполнения — для вызывающего кода, которого компилятор не видит: обычный JavaScript
или литерал, расширенный через переменную.

Второе предупреждение пакета срабатывает один раз на пакетный запрос, когда **команда** теряет
аргументы из-за нечитаемого ключа — прежде всего `query`, собственного написания портала в запросе
`restApi:v3`, где ключ SDK — `params`. Без предупреждения это незаметно:
команда уходит без аргументов, а портал отвечает HTTP 200 со значениями метода по умолчанию. См.
[BatchV3](/docs/actions/batch/) и
[BatchV2](/docs/actions/batch/).

::rest-api-version-only
#rest-api-ver2

> **Автоматические предупреждения**
>
> SDK автоматически отслеживает использование методов, доступных в REST API v3:
>
> ```json
> "The method {method_name} is available in restApi:v3. It's worth migrating to the new API."
> ```
>
> Это позволяет постепенно переходить с устаревшего API v2 на современный v3.

::

## Рекомендации по выбору метода

### Для получения данных

1. **Отдельные элементы** → используйте `Call`
2. **Списки, которые помещаются в память** → используйте `CallList`
3. **Большие списки (тысячи записей)** → используйте `FetchList`
4. **Несколько отдельных элементов** → используйте `Batch`

### Для изменения данных

1. **Одиночные операции** → используйте `Call`
2. **Массовые операции (до 50)** → используйте `Batch`
3. **Массовые операции (больше 50)** → используйте `BatchByChunk` или `DeferredBatch` (`restApi:v3`), если тариф портала поддерживает отложенные пакеты

### Для отладки и мониторинга

1. **Проверка доступности API** → используйте `HealthCheck`
2. **Измерение скорости ответа** → используйте `Ping`

## Лучшие практики

### Обработка ошибок

Всегда проверяйте `isSuccess` и обрабатывайте ошибки:

::rest-api-version-only
#rest-api-ver2
<!-- @check-ignore: top-level return in error-handling illustration -->
```typescript
const response = await $b24.actions.v2.call.make({
  method: 'some.method',
  params: { /* параметры */ },
  requestId: 'unique-id'
})

if (!response.isSuccess) {
  console.error('Error:', response.getErrorMessages().join('; '))
  // Дополнительная обработка ошибок
  return
}

// Работа с успешным результатом
const data = response.getData()
```

#rest-api-ver3
<!-- @check-ignore: top-level return in error-handling illustration; `some.method` is a placeholder, not a portal method -->
```typescript
const response = await $b24.actions.v3.call.make({
  method: 'some.method',
  params: { /* параметры */ },
  requestId: 'unique-id'
})

if (!response.isSuccess) {
  console.error('Error:', response.getErrorMessages().join('; '))
  // Дополнительная обработка ошибок
  return
}

// Работа с успешным результатом
const data = response.getData()
```
::

### Управление запросами

- `requestId`{lang="ts-type"} — всегда указывайте уникальный идентификатор запроса; это метка для отслеживания (`bx24_request_id`), а не ключ дедупликации; для дедупликации см. [`idempotencyKey`](/docs/actions/call/#idempotency-key)
- **Логирование** — используйте встроенные механизмы логирования для отладки
- **Таймауты** — настраивайте таймауты для долгих операций

## Миграция с REST API v2 на v3

Битрикс24 постепенно переходит на REST API версии 3. Рекомендуется:

1. **Следить за предупреждениями** SDK о доступности методов в v3
2. **Использовать** [документацию REST API v3](https://apidocs.bitrix24.com/api-reference/rest-v3/index.html)
3. **Запланировать миграцию** существующих проектов
