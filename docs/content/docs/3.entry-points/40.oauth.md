::caution{title="⚠️ ВНИМАНИЕ: БЕЗОПАСНОСТЬ"}
Объект `B24OAuth`{lang="ts-type"} предназначен **только для использования на сервере**.

- `clientSecret`, токен доступа и токен обновления не должны попадать в браузерный код.
- Предупреждение о клиентской стороне по умолчанию включено у обоих HTTP-клиентов; см. [`offClientSideWarning`](#offclientsidewarning).
- Для клиентских сценариев используйте [`B24Frame`](/docs/working-with-the-rest-api/frame/).
- При обработке обратных вызовов `ONAPPINSTALL` / `ONAPPUNINSTALL` проверяйте `application_token` перед любыми действиями — см. [Шаблоны безопасности для приёмников событий](/docs/working-with-the-rest-api/security/).
::

## Обзор

`B24OAuth`{lang="ts-type"} — точка входа SDK для [локальных приложений OAuth 2.0](https://apidocs.bitrix24.com/settings/oauth/index.html). Класс принимает готовую пару токенов (её выдаёт Битрикс24 при установке), использует токен доступа для REST-вызовов и обновляет пару через `oauth.bitrix.info`, когда токен доступа истекает.

Класс наследует `AbstractB24`{lang="ts-type"} и реализует [`TypeB24`{lang="ts-type"}](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/types/b24.ts). Весь REST-интерфейс (`actions.v2.*`, `actions.v3.*`, `tools.*`) доступен сразу после создания экземпляра — шага `await b24.init()` нет.

## Создание экземпляра B24OAuth

```ts
import { B24OAuth, EnumAppStatus } from '@bitrix24/b24jssdk'

const $b24 = new B24OAuth(
  // 1) Token data received from Bitrix24 (event payload, OAuth handshake, etc.)
  {
    applicationToken: '<your_application_token>',
    userId: 1,
    memberId: '<your_member_id>',
    accessToken: '<your_access_token>',
    refreshToken: '<your_refresh_token>',
    expires: 1745997853,        // unix timestamp, seconds
    expiresIn: 3600,            // seconds
    scope: 'crm,catalog,user_brief',
    domain: 'your_domain.bitrix24.com',
    clientEndpoint: 'https://your_domain.bitrix24.com/rest/',
    serverEndpoint: 'https://oauth.bitrix.info/rest/',
    status: EnumAppStatus.Free
  },
  // 2) Application credentials issued in Bitrix24 → Developers → Applications
  {
    clientId: 'local.xxxxxx.xxxxxx',
    clientSecret: '<your_client_secret>'
  }
)

const response = await $b24.actions.v2.call.make({
  method: 'tasks.task.list',
  params: { select: ['ID', 'TITLE', 'STATUS'] },
  requestId: 'tasks-list'
})
```

### Сигнатура конструктора

```ts-type
constructor(
  authOptions: B24OAuthParams,
  oAuthSecret: B24OAuthSecret,
  options?: {
    restrictionParams?: Partial<RestrictionParams>
    httpOptions?: TypeHttpOptions
  }
)
```

`options.restrictionParams` настраивает лимит частоты, лимит времени выполнения и адаптивную задержку — см. [Ограничители](/docs/working-with-the-rest-api/limiters/). `options.httpOptions` содержит настройки axios для обоих транспортов поверх значений SDK по умолчанию — прежде всего `adapter`; см. [Настройка экземпляра axios](/docs/working-with-the-rest-api/core-http/#настройка-экземпляра-axios). Ключи вне `TypeHttpOptions`{lang="ts-type"} отбрасываются при создании, их имена попадают в лог.

### Поля `B24OAuthParams`

| Поле | Тип | Описание |
|----|----|----|
| `applicationToken` | `string`{lang="ts-type"} | Токен приложения, выданный при установке. |
| `userId` | `number`{lang="ts-type"} | Идентификатор пользователя, которому принадлежит токен. |
| `memberId` | `string`{lang="ts-type"} | Идентификатор участника портала (member id). |
| `accessToken` | `string`{lang="ts-type"} | Текущий токен доступа. |
| `refreshToken` | `string`{lang="ts-type"} | Токен обновления, который использует `refreshAuth`. |
| `expires` | `number`{lang="ts-type"} | Время истечения токена доступа (unix timestamp в **секундах**). |
| `expiresIn` | `number`{lang="ts-type"} | Срок жизни токена, в секундах. |
| `scope` | `string`{lang="ts-type"} | Права доступа через запятую (например, `crm,catalog,user_brief`). |
| `domain` | `string`{lang="ts-type"} | Домен портала (`xxx.bitrix24.com`). |
| `clientEndpoint` | `string`{lang="ts-type"} | Корень REST портала, например `https://xxx.bitrix24.com/rest/`. |
| `serverEndpoint` | `string`{lang="ts-type"} | Сервер OAuth, обычно `https://oauth.bitrix.info/rest/`. |
| `status` | `TypeEnumAppStatus`{lang="ts-type"} | Одно из `EnumAppStatus.Free / Demo / Trial / Paid / Local / Subscription`. |

### Поля `B24OAuthSecret`

| Поле | Тип | Описание |
|----|----|----|
| `clientId` | `string`{lang="ts-type"} | OAuth `client_id` вашего приложения. |
| `clientSecret` | `string`{lang="ts-type"} | OAuth `client_secret` вашего приложения. |

## Обновление токена

`B24OAuth`{lang="ts-type"} автоматически обновляет токен доступа, когда:

- REST-вызов возвращает `expired_token`, **или**
- вызван `getAuthData()` и `expires <= Date.now()`.

Путь обновления по умолчанию отправляет `POST /oauth/token/` на `serverEndpoint` (сервер OAuth портала) с `grant_type=refresh_token`, переданными `refreshToken`, `clientId` и `clientSecret` в теле `application/x-www-form-urlencoded` — учётные данные никогда не попадают в строку запроса URL. При успехе менеджер обновляет `accessToken`, `refreshToken`, `expires`, `expiresIn`, `clientEndpoint`, `serverEndpoint`, `scope` и `status`.

Если запрос обновления не удался, SDK выбрасывает [`RefreshTokenError`](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/oauth/refresh-token-error.ts) (подкласс `SdkError`{lang="ts-type"}) с полями `code`, `description` и HTTP `status`.

### Сохранение обновлённых токенов

Зарегистрируйте обратный вызов, чтобы приложение могло сохранить новую пару токенов (в БД, менеджере секретов и т. п.):

// @check-ignore: B24OAuth-specific method, ambient $b24 is typed as B24Frame
```ts
$b24.setCallbackRefreshAuth(async ({ authData, b24OAuthParams }) => {
  await tokenStore.save({
    accessToken: b24OAuthParams.accessToken,
    refreshToken: b24OAuthParams.refreshToken,
    expires: b24OAuthParams.expires,
    expiresIn: b24OAuthParams.expiresIn,
    memberId: authData.member_id
  })
})
```

Снимается вызовом `$b24.removeCallbackRefreshAuth()`.

### Собственная логика обновления

Если ваше приложение получает токены обновления от отдельного сервиса (например, централизованного брокера токенов), передайте функцию `CustomRefreshAuth`{lang="ts-type"}. SDK вызовет её вместо обращения к `oauth.bitrix.info`:

// @check-ignore: B24OAuth-specific method, ambient $b24 is typed as B24Frame
```ts
import type { HandlerRefreshAuth } from '@bitrix24/b24jssdk'

$b24.setCustomRefreshAuth(async (): Promise<HandlerRefreshAuth> => {
  const fresh = await tokenBroker.fetch()
  return {
    access_token: fresh.accessToken,
    refresh_token: fresh.refreshToken,
    expires: fresh.expires,
    expires_in: fresh.expiresIn,
    client_endpoint: fresh.clientEndpoint,
    server_endpoint: fresh.serverEndpoint,
    member_id: fresh.memberId,
    scope: fresh.scope,
    status: fresh.status,
    domain: fresh.domain
  }
})
```

Снимается вызовом `$b24.removeCustomRefreshAuth()`.

## Методы

### `initIsAdmin`

```ts-type
initIsAdmin(requestId?: string): Promise<void>
```

Один раз вызывает REST-метод `profile` и кеширует, есть ли у авторизованного пользователя права администратора. Нужен перед чтением [`auth.isAdmin`](#getter-auth) — при слишком раннем обращении геттер выбрасывает `SdkError`{lang="ts-type"} с `code` `JSSDK_OAUTH_IS_ADMIN_NOT_INIT`{lang="ts-type"} (сообщение: `isAdmin not init. You need call B24OAuth::initIsAdmin().`).

// @check-ignore: B24OAuth-specific method, ambient $b24 is typed as B24Frame
```ts
await $b24.initIsAdmin('boot:isAdmin')
if ($b24.auth.isAdmin) {
  // ...
}
```

### `setCallbackRefreshAuth` / `removeCallbackRefreshAuth`

```ts-type
setCallbackRefreshAuth(cb: CallbackRefreshAuth): void
removeCallbackRefreshAuth(): void
```

Регистрирует и снимает обратный вызов, который выполняется после каждого успешного обновления. См. [Сохранение обновлённых токенов](#сохранение-обновлённых-токенов).

### `setCustomRefreshAuth` / `removeCustomRefreshAuth`

```ts-type
setCustomRefreshAuth(cb: CustomRefreshAuth): void
removeCustomRefreshAuth(): void
```

Регистрирует и снимает собственную реализацию обновления. См. [Собственная логика обновления](#собственная-логика-обновления).

### `offClientSideWarning`

```ts-type
offClientSideWarning(): void
```

Отключает предупреждение, которое выводится, когда `B24OAuth`{lang="ts-type"} обнаружен в браузерной среде — в основном потоке или в воркере (Web, Shared, Service Worker). Используйте, только если вы проксируете токены OAuth через серверную обёртку.

### `getTargetOrigin` / `getTargetOriginWithPath`

```ts-type
getTargetOrigin(): string
getTargetOriginWithPath(): Map<ApiVersion, string>
```

Возвращают origin портала (например, `https://xxx.bitrix24.com`) и REST-адреса по версиям API, полученные из `clientEndpoint`.

### `getHttpClient` / `setHttpClient` / `setRestrictionManagerParams` / `getLogger` / `setLogger` / `destroy`

Унаследованы от `AbstractB24`{lang="ts-type"} — те же, что у `B24Hook`{lang="ts-type"} и `B24Frame`{lang="ts-type"}. См.:

- [Ограничители](/docs/working-with-the-rest-api/limiters/) — `setRestrictionManagerParams`.
- [Логгер](/docs/working-with-the-rest-api/logger/) — `getLogger` / `setLogger`.

## Геттеры

### `auth`

Возвращает экземпляр [`AuthOAuthManager`](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/oauth/auth.ts), который реализует [`AuthActions`{lang="ts-type"}](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/types/auth.ts):

- `getAuthData()` — возвращает текущий `AuthData`{lang="ts-type"} или `false`{lang="ts-type"}, если токен доступа истёк (следующий REST-вызов запустит автоматическое обновление).
- `refreshAuth()` — ручное обновление; при сбое выбрасывает `RefreshTokenError`{lang="ts-type"}.
- `getUniq(prefix: string)` — возвращает `<prefix>_<memberId>`{lang="ts-type"}.
- `isAdmin` — сначала требуется `initIsAdmin()`.

### `isInit`

```ts-type
get isInit(): boolean
```

Сразу после создания всегда `true`{lang="ts-type"}.

## Обработка ошибок

// @check-ignore: top-level return in error-handling illustration
```ts
import { B24OAuth, RefreshTokenError } from '@bitrix24/b24jssdk'

try {
  const response = await $b24.actions.v3.call.make({
    method: 'tasks.task.get',
    params: { id: 1, select: ['id', 'title'] },
    requestId: 'task-get-1'
  })
  if (!response.isSuccess) {
    // Handle REST-level errors
    console.error(response.getErrorMessages())
  }
} catch (error) {
  if (error instanceof RefreshTokenError) {
    // Refresh token is dead — re-authorize the application
    console.error('OAuth refresh failed:', error.message)
    return
  }
  throw error
}
```

Неудачное обновление вызывает `RefreshTokenError`{lang="ts-type"}, если портал ответил полезной нагрузкой с ошибкой OAuth, а любой другой `Error`{lang="ts-type"} пробрасывается без изменений. До последнего варианта доходит только выброшенное значение, которое вообще **не** является `Error`{lang="ts-type"} — `new Error('Strange error: …')`{lang="ts-type"}: оно хранит это исходное значение в [`cause`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/cause), чтобы оно не потерялось.

## Частые вопросы

::accordion

:::accordion-item{label="Где взять начальную пару токенов?"}
Битрикс24 присылает их при установке вашего локального приложения и снова в событиях [`ONAPPINSTALL` / `ONAPPUPDATE`](https://apidocs.bitrix24.com/api-reference/events/index.html). Сохраните их и передавайте в `B24OAuth`{lang="ts-type"} при каждом запуске сервера.
:::

:::accordion-item{label="Почему `expires` в секундах, а не в миллисекундах?"}
Битрикс24 возвращает метки времени Unix в секундах. SDK преобразует их внутри; в `B24OAuthParams.expires` нужно передавать секунды.
:::

:::accordion-item{label="Можно ли использовать один экземпляр B24OAuth для всех запросов?"}
Да, и так и стоит делать. Общий экземпляр сохраняет согласованными состояние ограничителей и токен доступа в памяти. Сохраняйте обновлённую пару токенов через `setCallbackRefreshAuth`, чтобы после перезапуска использовались самые свежие токены.
:::

:::accordion-item{label="А методы только для чтения, которым не нужны права администратора?"}
`initIsAdmin()` можно пропустить, если ваш код никогда не читает `auth.isAdmin`. Сами REST-вызовы от него не зависят.
:::
