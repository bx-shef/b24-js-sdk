## Методы

### closeApplication
```ts-type
async closeApplication(): Promise<void>
```

Просит портал закрыть слайдер, в котором открыто ваше приложение.

```ts
declare function saveDraft(): Promise<void>

async function close() {
  // Сначала очистка: этот промис завершает только портал, а на некоторых сборках
  // он не отвечает никогда (#328) — и `await` ниже мог бы ждать вечно.
  await saveDraft()

  // `.catch`, потому что `destroy()` отклоняет команды, которые ещё в пути.
  $b24.parent.closeApplication().catch(() => {})
}
```

::warning
В некоторых сборках портала при закрытии внутри портала возникает исключение, и
последующая очистка пропускается. Слайдер закрывается, но на **родительской
странице** остаётся `inert`, и она игнорирует клики и фокус везде, пока её не
перезагрузят. Об этом сообщено команде ядра Битрикс24 в
[#328](https://github.com/bitrix24/b24jssdk/issues/328); SDK не может повлиять на
этот код. Если портал зависает после того, как ваше приложение закрылось само,
причина в этом, а не в вашем приложении.
::

### fitWindow
```ts-type
async fitWindow(): Promise<any>
```

Устанавливает размер фрейма приложения по размеру его содержимого.

### resizeWindow
```ts-type
async resizeWindow(width: number, height: number): Promise<void>
```

Изменяет размер фрейма приложения до указанных ширины и высоты.

### resizeWindowAuto
```ts-type
async resizeWindowAuto(
	appNode: null | HTMLElement = null,
	minHeight: number = 0,
	minWidth: number = 0
): Promise<void>
```

Автоматически изменяет размер `document.body` фрейма приложения по размеру его содержимого.

| Параметр | Тип | Описание |
|----|----|----|
| `appNode` | `null\|HTMLElement` | Узел приложения для расчёта высоты. |
| `minHeight` | `number` | Минимальная высота. |
| `minWidth` | `number` | Минимальная ширина. |

### setTitle
```ts-type
async setTitle(title: string): Promise<void>
```

Устанавливает заголовок страницы приложения — элемент заголовка в макете (`#pagetitle`), который Битрикс24 выводит вокруг вашего приложения. Заголовок вкладки браузера он не меняет.

Портал обрабатывает эту команду через `BX.ajax.UpdatePageTitle()`, которая переписывает элемент `#pagetitle`. Функцию `BX.ajax.UpdateWindowTitle()` (она задаёт `document.title`) портал не вызывает, поэтому заголовок вкладки браузера остаётся прежним — независимо от домена приложения и режима встройки.

| Контекст | Результат `setTitle()` |
|----|----|
| Страница приложения | Обновляет видимый заголовок страницы (`#pagetitle`). Вкладка браузера не меняется. |
| Слайдер | Затрагивает `#pagetitle` макета (часто невидимый); заголовок слайдера и вкладка браузера не меняются. |
| Встройка (placement, виджет) | Ограничено `#pagetitle` родительского макета, если он есть. Вкладка браузера не меняется. |

Чтобы заголовок попал во вкладку браузера, откройте представление как слайдер с опцией `bx24_title` (см. [`slider.openSliderAppPage`](/docs/entry-points/frame-slider/#opensliderapppage)):

```ts
await $b24.slider.openSliderAppPage({ bx24_title: 'Q1 2025 — John Smith' })
```

Чтобы полностью и динамически управлять заголовком вкладки браузера (например, различать несколько отдельных вкладок вашего приложения), приложение должно владеть документом верхнего уровня — то есть работать как отдельная страница вне iframe портала, где вы сами задаёте `document.title`.

### Методы `im*` работают по принципу «отправил и забыл»

Все четыре метода ниже отправляют порталу команду и **не могут узнать, сработала
ли она**. Обработчики этих команд на портале не принимают обратного вызова, поэтому
ответа не бывает; SDK завершает каждый вызов по собственному короткому таймеру.
Отсюда два следствия:

* возвращённый промис означает *команда отправлена*, а не *звонок начался* и не
  *чат открылся* — не используйте его как признак успеха;
* строка `action im… stop by timeout`, которую логгер пишет позже, — это
  **обычный** исход, а не сбой.

::warning
Любой из этих вызовов выводит в консоль **портала** уведомление об устаревании с
рекомендацией `Messenger.startPhoneCall` / `startVideoCall` / `openChat`. Это методы
окна верхнего уровня, и **из приложения они недоступны**: они не входят в набор
команд встройки (placement), а расширение, которое называет уведомление
(`im.public.iframe`), предназначено для iframe на собственном домене портала, а не
для фрейма приложения. Уведомление приходит из собственного слоя совместимости
портала, до которого методы ниже всё равно доходят; приложение избежать его не
может. Отслеживается в [#331](https://github.com/bitrix24/b24jssdk/issues/331).
::

### imCallTo
```ts-type
async imCallTo(userId: number, isVideo: boolean = true): Promise<void>
```

Начинает звонок через внутреннюю связь.

| Параметр  | Тип       | Описание                                            |
|-----------|-----------|-----------------------------------------------------|
| `userId`  | `number`  | Идентификатор пользователя.                         |
| `isVideo` | `boolean` | `true` — видеозвонок, `false` — аудиозвонок.        |

### imPhoneTo
```ts-type
async imPhoneTo(phone: string, params?: Record<string, unknown>): Promise<void>
```

Звонит на указанный номер телефона.

| Параметр  | Тип                         | Описание                                       |
|-----------|-----------------------------|------------------------------------------------|
| `phone`   | `string`                    | Номер телефона.                                |
| `params`  | `Record<string, unknown>`   | Дополнительные параметры менеджера телефонии.  |

`params` повторяет второй аргумент собственного метода портала
`Messenger.startPhoneCall(number, params)`. Портал его **пока не передаёт дальше** —
его обработчик моста читает только номер телефона, — поэтому отправка не даёт
эффекта. Параметр принят здесь, чтобы приложениям не пришлось меняться, когда
портал начнёт его передавать; неизвестное поле игнорируется, а не отклоняется.

### imOpenMessenger
```ts-type
async imOpenMessenger(dialogId: number|'chat${number}'|'sg${number}'|'imol|${number}'|undefined, messageId?: number): Promise<void>
```

Открывает окно мессенджера.

| Параметр    | Тип                                                               | Описание                                  |
|-------------|-------------------------------------------------------------------|-------------------------------------------|
| `dialogId`  | `number\|chat${number}\|sg${number}\|imol\|${number}\|undefined`  | Идентификатор диалога.                    |
| `messageId` | `number`                                                          | Сообщение, на которое нужно перейти после открытия. |

`messageId` повторяет второй аргумент `Messenger.openChat(dialogId,
messageId)` и, как `params` выше, **пока не передаётся порталом дальше**.

### imOpenHistory
```ts-type
async imOpenHistory(dialogId: number|'chat${number}'|'imol|${number}'): Promise<void>
```

Открывает окно истории сообщений.

| Параметр   | Тип                                       | Описание               |
|------------|-------------------------------------------|------------------------|
| `dialogId` | `number\|chat${number}\|imol\|${number}`  | Идентификатор диалога. |

Внутри портала этот метод идёт другим маршрутом, чем остальные три: для обычного
`dialogId` он приходит туда же, куда и `imOpenMessenger`, а для идентификатора
открытой линии (`imol|…`) уходит в отдельную ветку, публичный аналог которой —
`openLinesHistory`, а не `openChat`.
