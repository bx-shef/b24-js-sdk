## Геттеры

### title
```ts-type
get title(): string
```
Псевдоним [`placement`](#placement). Возвращает название встройки (`'DEFAULT'`, если родительское окно не передало название).

### `placement`
```ts-type
get placement(): string
```
Возвращает название встройки. Если название не задано, по умолчанию возвращает `'DEFAULT'`.

### isDefault
```ts-type
get isDefault(): boolean
```
Возвращает `true`, если название встройки — `'DEFAULT'`.

### options
```ts-type
get options(): Readonly<Record<string, unknown>>
```
Этот возвращаемый тип экспортируется как `PlacementOptions`{lang="ts-type"}, поэтому
вспомогательная функция, принимающая такие данные, может указать его по имени, а не
повторять развёрнутую запись:

```ts
import type { PlacementOptions } from '@bitrix24/b24jssdk'
```

Параметры, с которыми открыт этот фрейм, всегда в виде замороженного объекта —
заморозка только на один уровень, поэтому вложенное значение остаётся собственным
объектом портала. Сюда входят все параметры, которые вы передали в
[`slider.openSliderAppPage`](/docs/entry-points/frame-slider/#opensliderapppage),
именно так `place` попадает в новый фрейм.

**Значения имеют тип `unknown`{lang="ts-type"}, поэтому сузьте тип, прежде чем использовать
значение.** Эти данные приходят от портала через границу `postMessage`{lang="ts-type"};
тип говорит об этом прямо, а не делает вид, что это не так.

```ts
const place = $b24.placement.options['place']
if ('string' === typeof place) {
  console.log(`opened from ${place}`)
}
```

::note
**Четыре варианта входных данных нормализуются до того, как попадают сюда.** По
замерам на одной сборке в собственной инфраструктуре (`SM_VERSION 26.150.0`),
портал присылает **объект**, **пустую строку**, если встройка открыта вообще без
параметров, или **ничего** — именно это поймал #485, потому что
`Object.freeze(undefined)` равно `undefined`{lang="ts-type"}, а поле, объявленное как
`object`{lang="ts-type"}, всё равно его хранило. **JSON-строка** тоже обрабатывается,
хотя на этом пути её *не наблюдали*: она относится к маршруту повторной отправки
формы, а разбор стоит один `typeof`{lang="ts-type"}.

Каждый вариант превращается в объект, поэтому `options`{lang="ts-type"} никогда не
бывает `undefined`{lang="ts-type"} и не требует `?.`{lang="ts-type"} — пустая встройка
даёт пустой объект. Цена такого решения: отсутствующее значение, `''`, настоящий
пустой объект, массив и строку, которую нельзя разобрать, теперь не различить, а
доступа к исходному значению нет.
::

::warning
**Регистр ключей определяет портал, а не соглашение.** Для встройки по умолчанию
объект *и есть* строка запроса URL фрейма, поэтому ключи такие, какими их написал
тот, кто открывал встройку; для зарегистрированной встройки — такие, какими их
сохранило приложение при привязке. Не рассчитывайте на какой-то один регистр.
::

### isSliderMode
```ts-type
get isSliderMode(): boolean
```
Возвращает `true`, если виджет работает в режиме слайдера (опция `IFRAME` равна `'Y'`).

**Значение выводится из `PLACEMENT_OPTIONS.IFRAME`, поэтому не используйте его, чтобы
понять, пришли ли данные встройки вообще.** Привязывать к нему диагностику слайдера —
ловушка: флаг вычисляется из тех самых данных, отсутствие которых вы и пытаетесь
выяснить, поэтому строка в логе пропадает именно тогда, когда нужна.

```ts
// ... /////
$b24 = await initializeB24Frame()
// ... /////
if ($b24.placement.isSliderMode) {
	$b24.parent.setTitle('SliderMode') // updates the layout #pagetitle, not the slider header or browser tab
}
```

## Методы

### getInterface
```ts-type
async getInterface(): Promise<any>
```

Получает сведения о JS-интерфейсе текущего места встройки: список возможных команд и событий.

```ts
// ... /////
$b24 = await initializeB24Frame()
// ... /////
const value: any = await $b24.placement.getInterface()
```

### bindEvent
```ts-type
async bindEvent(
  eventName: string,
  callBack: (...args: any[]) => void
): Promise<any>
```

Устанавливает обработчик события интерфейса.

| Параметр    | Тип                         | Описание                                       |
|-------------|-----------------------------|------------------------------------------------|
| `eventName` | `string`                    | Название обрабатываемого события интерфейса.   |
| `callBack`  | `(...args: any[]) => void`  | Обработчик, который вызывается при событии.    |

### call
```ts-type
async call(command: 'setValue', parameters: { value: string }): Promise<any>
async call(command: string, parameters?: Record<string, any>): Promise<any>
```

Вызывает зарегистрированную команду интерфейса.

```ts
import { LoggerFactory } from '@bitrix24/b24jssdk'
// ... /////
const logger = LoggerFactory.createForBrowser('Demo', true)

$b24 = await initializeB24Frame()
// ... /////
$b24.placement.call('reloadData')
  .then((respose: any) => {
    logger.info('reload call')
  })
```

::warning
Команда `setValue` особая: родительское окно вызывает `JSON.parse(value)` для
полученных данных, поэтому `value` **должно** быть строкой с JSON. Если передать
обычную строку или объект напрямую, будет сбой (`SyntaxError` из `JSON.parse`
или тихое искажение до `"[object Object]"`).

Предпочитайте помощник [`setValue`](#setvalue), который сериализует значение за вас.
Если вы вызываете `call('setValue', ...)` напрямую, SDK выбросит `TypeError`, когда
`value` не строка.

```ts
// ✗ throws TypeError — value is not a string
await $b24.placement.call('setValue', { value: 'test' })

// ✓ works — value is a JSON string
await $b24.placement.call('setValue', { value: JSON.stringify('test') })
await $b24.placement.call('setValue', { value: JSON.stringify({ id: 1 }) })
```
::

### setValue
```ts-type
async setValue(value: unknown): Promise<any>
```

Удобная обёртка над `placement.call('setValue', ...)`, которая сама выполняет
`JSON.stringify` для значения. Принимает любое значение, которое можно
сериализовать в JSON (строка, число, логическое значение, объект, массив).

```ts
$b24 = await initializeB24Frame()
// ... /////
await $b24.placement.setValue('test')
await $b24.placement.setValue({ id: 1, title: 'demo' })
```

### callCustomBind
```ts-type
async callCustomBind(
  command: string,
  parameters: null | string | Record<string, any>,
  callBack: (...args: any[]) => void
): Promise<any>
```

Вызывает команду интерфейса и регистрирует обратный вызов, который получает последующие события этой команды. Используйте для команд, которые выдают события непрерывно (например, о ходе выполнения), а не завершаются один раз.

`parameters` принимает три вида значений:

- `null` — без данных.
- `string` — отправляется как `singleOption`.
- `Record<string, any>` — раскрывается в данные сообщения.

```ts
$b24 = await initializeB24Frame()
// ... /////
$b24.placement.callCustomBind('subscribe', { topic: 'crm:deal' }, (event) => {
  console.log('event', event)
})
```
