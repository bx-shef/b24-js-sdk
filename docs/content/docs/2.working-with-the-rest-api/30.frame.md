::note
Не вызывайте `new B24Frame(...)`{lang="ts-type"} напрямую — используйте [`initializeB24Frame()`](/docs/working-with-the-rest-api/frame-initialize-b24-frame/): он объединяет одновременные инициализации, разбирает данные `window.name`, переданные Битрикс24, и сам выполняет `await` для `init()`.
::

`B24Frame`{lang="ts-type"} наследует `AbstractB24`{lang="ts-type"} и реализует [`TypeB24`{lang="ts-type"}](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/types/b24.ts). Помимо общего REST-интерфейса (`actions.v2.*`, `actions.v3.*`, `tools.*`) класс предоставляет менеджеры, которые общаются с родительским окном через `postMessage`: `auth`, `parent`, `slider`, `dialog`, `placement`, `options`.

## Конструктор

```ts-type
constructor(
  queryParams: B24FrameQueryParams,
  options?: {
    restrictionParams?: Partial<RestrictionParams>
    httpOptions?: TypeHttpOptions
    keepAuthFresh?: boolean | KeepAuthFreshParams
  }
)
```

`httpOptions` — настройки axios для обоих транспортов, применяются поверх значений SDK по умолчанию — прежде всего `adapter`: в браузере SDK запрашивает `fetch`, а `{ adapter: 'xhr' }` возвращает прежнее поведение. [`initializeB24Frame()`](/docs/working-with-the-rest-api/frame-initialize-b24-frame/) передаёт их без изменений, поэтому обращаться к конструктору ради них не нужно. Ключи вне `TypeHttpOptions`{lang="ts-type"} отбрасываются при создании, их имена попадают в лог. См. [Настройка экземпляра axios](/docs/working-with-the-rest-api/core-http/#configuring-the-axios-instance).

[`B24FrameQueryParams`{lang="ts-type"}](https://github.com/bitrix24/b24jssdk/blob/main/packages/jssdk/src/types/auth.ts) описывает идентификаторы, которые Битрикс24 передаёт в `window.name`:

| Поле       | Тип       | Описание                           |
|------------|-----------|------------------------------------|
| `DOMAIN`   | `string`{lang="ts-type"}  | Домен портала Битрикс24.             |
| `PROTOCOL` | `boolean`{lang="ts-type"} | Флаг протокола соединения.           |
| `LANG`     | `string`{lang="ts-type"}  | Язык интерфейса Битрикс24.           |
| `APP_SID`  | `string`{lang="ts-type"}  | Идентификатор сессии приложения.     |

В отличие от `B24Hook`{lang="ts-type"} и `B24OAuth`{lang="ts-type"}, `B24Frame`{lang="ts-type"} требует `await b24.init()` перед любым REST-вызовом — `init()` выполняет обмен `getInitData` с родительским окном. `initializeB24Frame()` делает это за вас.

## Геттеры

### `isInit`

```ts-type
get isInit(): boolean
```

`true`{lang="ts-type"}, когда обмен с родительским окном завершён. До этого обращение к `auth`, `actions`, `tools` или любому менеджеру фрейма выбрасывает `'B24 not initialized'`{lang="ts-type"}.

### `isFirstRun`

```ts-type
get isFirstRun(): boolean
```

`true`{lang="ts-type"} при самом первом запуске приложения (Битрикс24 устанавливает `FIRST_RUN`). При `isFirstRun = true`{lang="ts-type"} SDK автоматически отправляет родителю `setInstall: true`.

### `isInstallMode`

```ts-type
get isInstallMode(): boolean
```

`true`{lang="ts-type"}, пока приложение находится в процессе установки (флаг `INSTALL` от родителя). Нужен для [`installFinish`](#installfinish).

### `auth`

```ts-type
get auth(): AuthManager
```

[Менеджер авторизации](/docs/working-with-the-rest-api/frame-auth/). Предоставляет `getAuthData`, `refreshAuth`, `getUniq`, `isAdmin`, а также автоматически обновляет истёкший токен на пути запроса (перед вызовом и ещё раз при ответе 401).

`keepAuthFresh` закрывает случай, который этот путь не покрывает: приложение, которое читает токен и использует его вне SDK, не делает запросов, поэтому токен никто не обновляет. См. [Сохранение токена актуальным](/docs/working-with-the-rest-api/frame-initialize-b24-frame/#сохранение-токена-актуальным).

### `parent`

```ts-type
get parent(): ParentManager
```

[Менеджер родительского окна](/docs/working-with-the-rest-api/frame-parent/). Отправка сообщений на окружающую страницу Битрикс24 и чтение её метаданных.

### `slider`

```ts-type
get slider(): SliderManager
```

[Менеджер слайдера](/docs/working-with-the-rest-api/frame-slider/). Открытие и закрытие слайдеров Битрикс24.

### `placement`

```ts-type
get placement(): PlacementManager
```

[Менеджер встройки (placement)](/docs/working-with-the-rest-api/frame-placement/). Просмотр и обновление контекста встройки.

### `options`

```ts-type
get options(): OptionsManager
```

[Менеджер опций](/docs/working-with-the-rest-api/frame-options/). Чтение опций приложения и пользователя, синхронизированных из родительского окна.

### `dialog`

```ts-type
get dialog(): DialogManager
```

[Менеджер диалогов](/docs/working-with-the-rest-api/frame-dialog/). Запрос к Битрикс24 на показ собственных диалогов подтверждения, сообщений и выбора файлов.

## Методы

### `init`

```ts-type
init(): Promise<void>
```

Выполняет обмен с родительским окном (`getInitData`), настраивает состояние менеджеров и создаёт оба HTTP-клиента REST API. На практике идемпотентен — `initializeB24Frame()` объединяет одновременные вызовы.

### `destroy`

```ts-type
destroy(): void
```

Завершает работу фрейма: отписывается от событий `postMessage`, сбрасывает таймеры ожидающих команд и удаляет обратные вызовы встроек. Всегда вызывайте перед размонтированием родительского компонента, чтобы не было утечек.

Любая команда, которая всё ещё ждёт ответа родительского окна, **отклоняется** с кодом `JSSDK_FRAME_DISPOSED`, а не остаётся в ожидании: после снятия слушателя ответить на неё некому, а молчание — единственный исход, на который вызывающий код не может отреагировать. Так же ведёт себя уничтоженный `PullClient`: `start()` отклоняется с `PULL_DISPOSED`.

Это важно для команды, чей промис вы не ожидаете. Обычная пара — `parent.closeApplication()` и `slider.closeSliderAppPage()`: они выполняются как раз при закрытии приложения. Если вы вызвали одну из них без `await` и тут же уничтожили фрейм, добавьте `.catch(() => {})`, чтобы отклонение не превратилось в необработанное.

### `installFinish`

```ts-type
installFinish(): Promise<any>
```

Отправляет родителю `setInstallFinish`. Возвращаемый промис **отклоняется** с `SdkError`{lang="ts-type"}, у которого `code` равен `JSSDK_FRAME_INSTALL_ALREADY_FINISHED`{lang="ts-type"} (сообщение: `Application was previously installed. You cannot call installFinish`), если метод вызван вне режима установки, — проверяйте `isInstallMode`. Отказ локальный: `status`{lang="ts-type"} равен `0`{lang="ts-type"}, в родительское окно ничего не отправляется.

Есть **второй** случай сбоя с другим кодом. Если вызвать метод до завершения `init()`{lang="ts-type"}, он отклоняется с `JSSDK_CORE_B24_NOT_INIT`{lang="ts-type"} — его выбрасывает геттер `isInstallMode`{lang="ts-type"}, который читает метод, — поэтому вызывающий код, различающий ошибки по коду выше, его пропустит. Этот случай возможен, только если вы сами создаёте `B24Frame`{lang="ts-type"}: `initializeB24Frame()`{lang="ts-type"} сам ожидает `init()`{lang="ts-type"}.

::warning
**Приложение с интерфейсом установки, которое не вызывает этот метод, остаётся установленным наполовину, и портал не доставляет ему события.** Обработчики, привязанные через `event.bind`, не срабатывают, встройки, привязанные через `placement.bind`, не появляются, а другие исходящие вызовы не доходят до ваших адресов — хотя каждый из этих вызовов регистрации вернул успех.

Это задокументированное поведение Битрикс24: [Что не работает до завершения установки](https://apidocs.bitrix24.com/settings/app-installation/installation-finish.html#what-doesnt-work-until-installation-is-complete) называет именно `placement.bind` и `event.bind` неработающими, пока установка не завершена. (Авторитетный источник здесь эта страница: SDK не может воспроизвести поведение портала, поэтому если вы видите иное, например на портале в собственной инфраструктуре, доверяйте проверке `app.info` ниже, а не этому тексту.)

Ничего не падает с ошибкой. Регистрация проходит, `imbot.register` возвращает `botId`, запрос списка показывает обработчики — а трафик так и не приходит. Все видимые признаки говорят, что настройка верна, поэтому причину обычно ищут не на том уровне: nginx, туннели, TLS, маршрутизация.

Вызывайте метод один раз со страницы установки, последним шагом процесса установки.

**Это относится только к приложению с интерфейсом установки.** Приложение только для API без интерфейса *не должно* вызывать `installFinish()` — его установка завершается автоматически, а метод работает только внутри фрейма с браузерным интерфейсом (обратный вызов установки выполняется на сервере и вызвать его не может). Поэтому если приложению без интерфейса не хватает событий, причина не в `installFinish()` — ищите в другом месте.

Завершение установки — это шаг **жизненного цикла**, а не безопасности. Приложение, у которого есть OAuth-обработчики установки и удаления, всё равно должно проверять `application_token` в `ONAPPINSTALL` / `ONAPPUNINSTALL` — см. [Шаблоны безопасности](/docs/working-with-the-rest-api/security/). Эти вещи не связаны, и выполнение одной не заменяет другую.

Чтобы проверить приложение уже после установки, спросите портал:

```ts
const response = await $b24.actions.v2.call.make<{ INSTALLED: boolean }>({
  method: 'app.info',
  requestId: 'app-info-1'
})
console.log(response.getData()!.result.INSTALLED) // false ⇒ installFinish() never landed
```
::

::note
Портал реагирует на этот вызов **перезагрузкой страницы**: из установщика он перезапускает приложение, а на этапе настроек заново запускает обработчики `init`.

Это сильнее, чем «следующая строка может не выполниться». Эта команда отправляется без таймера `isSafely` из SDK, поэтому её промис завершается только когда отвечает родительское окно, — а если перезагрузка случится раньше, **промис не завершится вообще**. `await` не вернётся, а прикреплённый к нему блок `finally` не выполнится. Считайте `installFinish()` последним оператором процесса установки и не строите состояние, которое зависит от его завершения.
::

## Использование

```ts
import {
  initializeB24Frame,
  LoggerFactory,
  EnumCrmEntityTypeId,
  Text,
  type B24Frame,
  type ISODate
} from '@bitrix24/b24jssdk'

const $logger = LoggerFactory.createForBrowser('MyApp', import.meta.env?.DEV === true)
let $b24: undefined | B24Frame

async function loadCompanies() {
  if (!$b24) return

  const response = await $b24.actions.v2.callList.make<{ id: number, title: string, createdTime: ISODate }>({
    method: 'crm.item.list',
    params: {
      entityTypeId: EnumCrmEntityTypeId.company,
      select: ['id', 'title', 'createdTime']
    },
    idKey: 'id',
    requestId: 'companies-list'
  })

  if (!response.isSuccess) {
    $logger.error('REST error', { messages: response.getErrorMessages() })
    return
  }

  return response.getData()!.map((item) => ({
    id: Number(item.id),
    title: item.title,
    createdTime: Text.toDateTime(item.createdTime)
  }))
}

async function bootstrap() {
  try {
    $b24 = await initializeB24Frame()
    const companies = await loadCompanies()
    $logger.notice('companies', { companies })
  } catch (error) {
    $logger.error('init failed', { error })
  }
}

bootstrap()
```

::note
Страница должна работать как [приложение Битрикс24](https://apidocs.bitrix24.com/api-reference/app-installation/local-apps/index.html) (внутри iframe встройки). Вне этого контекста обмен с родительским окном не завершается.
::
