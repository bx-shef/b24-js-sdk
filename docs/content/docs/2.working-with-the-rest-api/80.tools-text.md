## Обзор

`Text`{lang="ts-type"} — синглтон (`new TextManager()`), экспортируемый из `@bitrix24/b24jssdk`. Он объединяет небольшие помощники для текста и дат, на которые SDK опирается внутри, и предоставляет их коду приложения:

- **Идентификаторы** — случайные строки, локально сгенерированный UUID v4 и упорядоченный по времени UUID v7 (идентификатор запроса по умолчанию в SDK).
- **Кодирование HTML-сущностей** — `encode` / `decode` в стиле прежнего Bitrix Framework.
- **Преобразование типов** — приведение произвольных значений к числам, целым числам и булевым значениям.
- **Помощники регистра** — `camelCase`, `PascalCase`, `kebab-case` и `capitalize`.
- **Форматирование чисел** — разряды тысяч и фиксированное число знаков после запятой.
- **Помощники дат** — разбор на основе [Luxon](https://moment.github.io/luxon/) и формат `yyyy-MM-dd'T'HH:mm:ssZZ`, который Битрикс24 ожидает в полезной нагрузке REST.
- **Строки запроса** — построение строки `application/x-www-form-urlencoded` из простого объекта.

```ts
import { Text } from '@bitrix24/b24jssdk'

console.log(Text.getUuidRfc4122())          // '019323ac-8ace-725b-a3dc-6a7c333da066'
console.log(Text.getDateForLog())           // '2026-05-04 09:53:51'
console.log(Text.numberFormat(1234.567, 2)) // '1,234.57'
```

## Сигнатура метода

### Идентификаторы

```ts-type
getRandom(length?: number): string          // random [a-z0-9], default length 8
getUniqId(): string                          // UUID v4 (best-effort, local)
getUuidRfc4122(): string                     // UUID v7 (time-ordered) — SDK default request id
```

### Кодирование сущностей

```ts-type
encode(value: string): string                // & < > ' "  → entity codes (no trailing ;)
decode(value: string): string                // inverse of encode, also numeric entities
```

### Преобразование типов

```ts-type
toNumber(value: any): number                 // 0 on parse failure
toInteger(value: any): number                // toNumber(parseInt(value, 10))
toBoolean(value: any, trueValues?: string[]): boolean // 'true'/'y'/'1'/1/true → true
```

### Помощники регистра

```ts-type
toCamelCase(str: string): string
toPascalCase(str: string): string            // capitalize(toCamelCase(str))
toKebabCase(str: string): string
capitalize(str: string): string
```

### Форматирование чисел

```ts-type
numberFormat(
  number: number,
  decimals?: number,        // default 0
  decPoint?: string,        // default '.'
  thousandsSep?: string     // default ','
): string
```

### Помощники дат (Luxon)

```ts-type
toDateTime(dateString: string, template?: string, opts?: DateTimeOptions): DateTime
toB24Format(date: string | Date | DateTime): string   // yyyy-MM-dd'T'HH:mm:ssZZ
getDateForLog(): string                                // 'yyyy-MM-dd HH:mm:ss'
```

### Строка запроса

```ts-type
buildQueryString(params: any): string        // application/x-www-form-urlencoded, no leading '?'
```

## Ключевые понятия

::note
`encode` / `decode` намеренно опускают завершающий `;` (например, `&amp` вместо `&amp;`). Это соответствует поведению прежнего Bitrix Framework. `decode` обращает этот вывод и также распознаёт числовые сущности (`&#38`, `&#60`, …). Поскольку в токенах нет `;`, завершающий `;` во входных данных остаётся на месте (`&amp;` → `&;`).
::

::caution
`encode` — **не** универсальный санитайзер HTML. Он экранирует только `&`, `<`, `>`, `'` и `"` и не учитывает контекст — он не остановит выход из атрибута, URL `javascript:` или разметку вне этих пяти символов. Не используйте его как единственную защиту от XSS для недоверенного ввода, выводимого как HTML.
::

- **`getRandom` / `getUniqId` не являются криптографически стойкими.** Оба строятся на `Math.random()` — используйте их для ключей сброса кеша и одноразовых идентификаторов, но не для токенов и секретов.
- **Разделители в `toCamelCase`.** Границами слов считаются `-`, `_` и пробельные символы; ввод целиком в верхнем регистре приводится к нижнему (`'ABC'` → `'abc'`).
- **`toKebabCase` делит по границам регистра.** `getUserId` → `get-user-id` и `XMLHttpRequest` → `xml-http-request`, поэтому обрабатываются `camelCase` и аббревиатуры в смешанном регистре. Один крайний случай: последовательность заглавных букв, за которой сразу идёт цифра, делится по буквам (`parseHTML5` → `parse-h-t-m-l-5`).
- **`numberFormat` соответствует серверу.** Нечисловые значения становятся `0`, дробная часть округляется до `decimals` знаков, а разделитель тысяч вставляется через каждые три цифры слева от десятичной точки.
- **`toDateTime` возвращает `DateTime` даже для некорректного ввода.** Если задан `template`, используется `DateTime.fromFormat`, иначе `DateTime.fromISO`. Перед использованием проверьте `result.isValid`.
- **`toB24Format` пропускает строки без изменений** (считается, что они уже отформатированы); JS `Date` сначала нормализуется через Luxon.

## Обработка ошибок

Помощники `Text` не выбрасывают исключений при неожиданном вводе — они деградируют мягко: `toNumber` / `toInteger` возвращают `0`, `toBoolean` возвращает `false`, `buildQueryString(null)` возвращает `''`, а `encode` / `decode` возвращают нестроковые значения без изменений. `toDateTime` тоже никогда не выбрасывает исключение — для нераспознаваемого ввода он возвращает `DateTime` с флагом `isValid`, равным `false`, поэтому проверяйте `result.isValid` перед использованием значения.

## Примеры

Идентификаторы и идентификаторы запросов:

```ts
import { Text } from '@bitrix24/b24jssdk'

Text.getRandom()          // 'a7f3k1z9'
Text.getRandom(4)         // 'p2x8'
Text.getUniqId()          // 'd2b8a1f0-3c4e-4a9b-8f7c-1e2d3a4b5c6d'  (UUID v4)
Text.getUuidRfc4122()     // '019323ac-8ace-725b-a3dc-6a7c333da066'  (UUID v7)
```

Кодирование и преобразование типов:

```ts
import { Text } from '@bitrix24/b24jssdk'

Text.encode('<b>Tom & Jerry</b>') // '&ltb&gtTom &amp Jerry&lt/b&gt'
Text.decode('&ltb&gtTom &amp Jerry&lt/b&gt') // '<b>Tom & Jerry</b>'

Text.toNumber('12.5')     // 12.5
Text.toInteger('42.9')    // 42
Text.toBoolean('Y')       // true
Text.toBoolean('on', ['on']) // true
```

Помощники регистра и форматирование чисел:

```ts
import { Text } from '@bitrix24/b24jssdk'

Text.toCamelCase('get_user_id')  // 'getUserId'
Text.toPascalCase('get_user_id') // 'GetUserId'
Text.toKebabCase('getUserId')    // 'get-user-id'
Text.capitalize('hello')         // 'Hello'

Text.numberFormat(1234.567, 2)           // '1,234.57'
Text.numberFormat(1234.567, 2, ',', ' ') // '1 234,57'
```

Даты и строки запроса:

```ts
import { Text } from '@bitrix24/b24jssdk'

// Format a date for a REST payload
Text.toB24Format(new Date()) // '2026-05-04T09:53:51+03:00'

// Parse an ISO string or a custom template
const dt = Text.toDateTime('04.05.2026', 'dd.MM.yyyy')
if (dt.isValid) {
  console.log(dt.toISODate()) // '2026-05-04'
}

// Build a query string (leading '?' is not included)
Text.buildQueryString({ id: 7, tag: ['a', 'b'] })
// 'id=7&tag%5B0%5D=a&tag%5B1%5D=b'
```

## Альтернативы и рекомендации

- **Предпочитайте `getUuidRfc4122()` вместо `getUniqId()`.** Идентификатор v7 упорядочен по времени и соответствует RFC 4122, поэтому SDK использует его как идентификатор запроса по умолчанию. Обращайтесь к `getUniqId()` (UUID v4) только когда вам нужен именно случайный несортируемый идентификатор, а когда нужна криптографическая случайность — ни к одному из них.
- **Используйте `toB24Format` для каждой даты, которую вы отправляете в REST API.** Передача «сырого» `Date` или ISO-строки с неверным смещением — самая частая причина несовпадения фильтров; примеры фильтров по диапазону дат см. в разделе [Фильтрация](/docs/working-with-the-rest-api/filtering/).
- **Проверки типов во время выполнения находятся в [`Type`](/docs/working-with-the-rest-api/tools-type/).** `Text` сосредоточен на преобразовании; используйте защиты `Type` (`isStringFilled`, `isArrayFilled`, …), когда нужно сначала ветвиться по форме значения.
- **Форматирование валют и IBAN с учётом локали находится в [`useFormatter`](/docs/working-with-the-rest-api/tools-use-formatters/).** `numberFormat` — лёгкий помощник для тысяч и десятичных знаков; для вывода валюты, процентов или IBAN используйте специальные форматтеры.
- **Для всего сложнее разбора работайте с Luxon напрямую.** `toDateTime` — тонкая обёртка над `DateTime.fromISO` / `DateTime.fromFormat`; для арифметики, часовых поясов и длительностей импортируйте `DateTime` из `luxon` и работайте с возвращённым значением.
