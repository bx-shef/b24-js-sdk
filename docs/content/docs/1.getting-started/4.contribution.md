Bitrix24 JS SDK — открытый проект: мы рады сообщениям об ошибках, pull request'ам и отзывам.

::caution
Перед тем как сообщать об ошибке или предлагать новую возможность, прочитайте [документацию](https://bitrix24.github.io/b24jssdk/) и просмотрите существующие [issues](https://github.com/bx-shef/b24-js-sdk/issues?q=is%3Aissue+is%3Aopen+sort%3Aupdated-desc).

## Работа с ИИ-помощниками

Правила для ИИ-агентов собраны в [`AGENTS.md`](https://github.com/bx-shef/b24-js-sdk/blob/main/AGENTS.md): его автоматически подхватывают ИИ-агенты для программирования. Он описывает структуру проекта, архитектуру, соглашения о коде, рабочие процессы и чек-лист ревью. Подробные руководства по областям лежат в [`.github/contributing/`](https://github.com/bx-shef/b24-js-sdk/tree/main/.github/contributing), а готовые навыки для задач — в каталоге [`skills/`](/docs/getting-started/ai/skills/).

## Структура проекта

```text
├── packages/
│   ├── jssdk/          # ядро SDK (@bxshefby/b24jssdk)
│   └── jssdk-nuxt/     # модуль Nuxt (@bxshefby/b24jssdk-nuxt)
├── docs/               # сайт документации (Nuxt + @nuxt/content)
│   ├── app/            # оформление, компоненты, композаблы
│   ├── server/         # MCP-инструменты, raw-страницы, llms
│   └── content/docs/   # страницы документации
├── playgrounds/        # песочницы (nuxt, cli)
├── skills/             # навыки для ИИ-агентов
├── test/               # тесты ядра
└── scripts/            # проверки документации и сборки
```

### Документация

Страницы лежат в `docs/content/docs/`, их имена — kebab-case с числовым префиксом, который задаёт порядок в навигации:

```text
docs/content/docs/
├── 1.getting-started/   # быстрый старт: установка, миграция, участие в разработке, ИИ
├── 2.actions/           # действия: call, callList, fetchList, batch и руководства
├── 3.entry-points/      # точки входа: B24Hook, B24Frame, B24OAuth, помощники, Pull
├── 4.tools/             # инструменты: логгер, лимитеры, ядро, утилиты, типы, коды ошибок
├── 5.api-reference/     # справочник API
└── 99.examples/         # примеры
```

Правила оформления страниц (frontmatter, скелет страницы действия, блок `links`, поле `audited`) — в [руководстве по документации](https://github.com/bx-shef/b24-js-sdk/blob/main/.github/contributing/documentation.md).

## Локальная разработка

::steps{level="4"}

#### Клонируйте репозиторий

```bash
git clone https://github.com/bx-shef/b24-js-sdk.git
```

#### Включите [Corepack](https://github.com/nodejs/corepack)

```bash
corepack enable
```

#### Установите зависимости

```bash
pnpm install
```

#### Подготовьте заглушки типов

```bash
pnpm run dev:prepare
```

#### Запустите разработку

- Работа над **документацией** (каталог `docs`):

```bash
pnpm run docs:dev
```

- Проверка модуля Nuxt в **песочнице**:

```bash
pnpm run playground-nuxt:dev
```

::

### Линтер

```bash
pnpm run lint       # проверить код
pnpm run lint:fix   # исправить замечания
```

### Проверка типов

```bash
pnpm run typecheck
```

### Тесты

Модульные тесты не требуют портала Битрикс24:

```bash
pnpm run package-jssdk:test:run-unit
```

Интеграционные тесты ходят на настоящий портал — как их запускать и какие переменные окружения нужны, описано в [руководстве по тестированию](https://github.com/bx-shef/b24-js-sdk/blob/main/.github/contributing/testing.md).

### Проверки документации

```bash
node scripts/docs-lint.mjs --strict
node scripts/docs-link-check.mjs
node scripts/md-internal-links.mjs
pnpm run docs:typecheck-blocks
```

## Соглашения о коммитах

Мы используем [Conventional Commits](https://www.conventionalcommits.org/): из заголовков коммитов автоматически собирается список изменений.

- `fix` и `feat` — изменения кода, затрагивающие поведение или логику;
- `docs` — изменения только документации, `chore` — обслуживание;
- ломающее изменение помечается `!` после типа (`feat(call)!: …`) либо строкой `BREAKING CHANGE:` в теле коммита.

## Pull request

1. Создайте ветку от `main`.
2. Перед коммитом выполните `pnpm run lint:fix` и `pnpm run typecheck`.
3. Обновите документацию в **том же** PR, если изменилась публичная поверхность SDK.
4. Откройте PR и опишите, что и зачем изменено; PR сливаются через squash.

::note
Репозиторий — форк [bitrix24/b24jssdk](https://github.com/bitrix24/b24jssdk). Правки кода SDK, полезные и родителю, лучше предлагать там: изменения родителя регулярно переносятся в этот репозиторий.
::
