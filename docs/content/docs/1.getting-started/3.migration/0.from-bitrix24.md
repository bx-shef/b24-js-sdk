Эта библиотека выходит под именами `@bxshefby/b24jssdk` и `@bxshefby/b24jssdk-nuxt`. Версия `3.1.0` совместима с `@bitrix24/b24jssdk@3.0.0`: те же классы, методы и типы, поэтому переход — это смена имени пакета, а не правка кода.

Есть два способа перейти.

## Без правки кода: псевдоним пакета

npm, pnpm и yarn умеют ставить пакет под другим именем. Зависимость остаётся `@bitrix24/b24jssdk`, а код и импорты не меняются:

```json [package.json]
{
  "dependencies": {
    "@bitrix24/b24jssdk": "npm:@bxshefby/b24jssdk@^3.1.0"
  }
}
```

После правки `package.json` выполните установку (`npm install`, `pnpm install` или `yarn`), чтобы обновился lock-файл.

Этот способ удобен для большого проекта, который нужно перевести без правки исходников. Примеры в этой документации написаны с именем `@bxshefby/b24jssdk`: при копировании кода в такой проект имя в импорте придётся поменять на `@bitrix24/b24jssdk`.

::warning
**Для Nuxt-модуля псевдоним не подходит.** `@bxshefby/b24jssdk-nuxt` зависит от `@bxshefby/b24jssdk` по его собственному имени, а npm и yarn ставят псевдоним отдельной копией. В приложении оказываются две копии SDK: плагин создаёт фрейм из одной, а код импортирует из другой. Проект на Nuxt переводите сменой имени пакета.
::

## Смена имени пакета

1. Для Nuxt сначала уберите строку `'@bitrix24/b24jssdk-nuxt'` из `modules` в `nuxt.config.ts`: иначе установка, которая запускает `nuxt prepare`, остановится на модуле, которого уже нет.

2. Удалите старые пакеты и поставьте новые:

   ```bash
   npm uninstall @bitrix24/b24jssdk @bitrix24/b24jssdk-nuxt
   npm install @bxshefby/b24jssdk
   ```

   Для Nuxt добавьте модуль — команда сама допишет его в `modules`: `npx nuxi module add @bxshefby/b24jssdk-nuxt`.

3. Замените имя в импортах: `'@bitrix24/b24jssdk'` → `'@bxshefby/b24jssdk'`, `'@bitrix24/b24jssdk-nuxt'` → `'@bxshefby/b24jssdk-nuxt'`.

4. Проверьте, что старых имён не осталось:

   ```bash
   grep -rn "@bitrix24/b24jssdk" --include="*.ts" --include="*.tsx" --include="*.vue" --include="*.js" --include="*.mjs" --include="*.cjs" --include="*.json" . | grep -v node_modules
   ```

## Подключение через `<script>`

Глобальная переменная сборки UMD та же — `B24Js`. Меняется только адрес файла:

```html
<script src="https://unpkg.com/@bxshefby/b24jssdk@3/dist/umd/index.min.js"></script>
```

## Что остаётся прежним

- Классы, методы, типы и коды ошибок — как в `@bitrix24/b24jssdk@3.0.0`.
- Требования к среде: Node 22 и новее.

Кеш настроек Pull-клиента в `localStorage` хранится под ключами с новым именем пакета: после перехода клиент один раз заново запросит настройки у портала. Подписки и данные приложения это не затрагивает.

Если вы переходите со старой линейки `2.x`, сначала смотрите [миграцию на v3](/docs/getting-started/migration/v3/).
