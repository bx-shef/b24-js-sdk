## Цель

Получить все сделки CRM, закрытые за выбранный период, с портала Битрикс24 и записать их в CSV-файл. Расход памяти остаётся постоянным независимо от того, сколько сделок подошло: `FetchListV2.make()` потоково загружает страницы по 50 записей.

## Стек и требования

- Node.js 20+, ESM (`"type": "module"` в `package.json`)
- `@bitrix24/b24jssdk@^1.0.0`
- URL входящего вебхука Битрикс24 с правом доступа (scope) `crm`. Задайте его как `B24_HOOK` в окружении.

```bash
pnpm add @bitrix24/b24jssdk
export B24_HOOK="https://your-portal.bitrix24.com/rest/1/xxxxxxxxxxxxxxxx/"
```

## Полный пример

`scripts/deals-to-csv.mjs`:

```js
import { writeFile } from 'node:fs/promises'
import {
  B24Hook,
  EnumCrmEntityTypeId,
  ParamsFactory,
  Text
} from '@bitrix24/b24jssdk'

const hookUrl = process.env.B24_HOOK
if (!hookUrl) {
  console.error('B24_HOOK is not set')
  process.exit(1)
}

// Closed in the previous calendar month.
const now = new Date()
const from = new Date(now.getFullYear(), now.getMonth() - 1, 1)
const to = new Date(now.getFullYear(), now.getMonth(), 1)

const b24 = B24Hook.fromWebhookUrl(hookUrl, {
  // Lower per-second pressure than `getDefault()` — good for reporting jobs
  // that run alongside live user traffic on the same portal.
  restrictionParams: ParamsFactory.getBatchProcessing()
})

const generator = b24.actions.v2.fetchList.make({
  method: 'crm.item.list',
  params: {
    entityTypeId: EnumCrmEntityTypeId.deal,
    filter: {
      '>=closedAt': Text.toB24Format(from),
      '<closedAt': Text.toB24Format(to),
      stageSemanticId: 'S' // closed-won
    },
    select: ['id', 'title', 'opportunity', 'currencyId', 'closedAt', 'assignedById']
  },
  idKey: 'id',
  customKeyForResult: 'items',
  requestId: 'deals-to-csv'
})

const rows = ['id;title;amount;currency;closedAt;assignedById']
let count = 0
for await (const chunk of generator) {
  for (const deal of chunk) {
    rows.push([
      deal.id,
      JSON.stringify(deal.title ?? ''),
      deal.opportunity ?? '',
      deal.currencyId ?? '',
      deal.closedAt ?? '',
      deal.assignedById ?? ''
    ].join(';'))
  }
  count += chunk.length
  process.stderr.write(`fetched: ${count}\r`)
}

const file = `deals-${from.toISOString().slice(0, 7)}.csv`
await writeFile(file, rows.join('\n'), 'utf8')
console.log(`\nwrote ${count} rows to ${file}`)
```

## Запуск

```bash
node scripts/deals-to-csv.mjs
# fetched: 4350
# wrote 4350 rows to deals-2026-04.csv
```

## Как это работает

- `B24Hook.fromWebhookUrl()` разбирает URL вебхука и возвращает настроенный экземпляр `TypeB24`; инициализация через `await` не нужна.
- `ParamsFactory.getBatchProcessing()` заменяет профиль ограничения частоты по умолчанию на профиль для долгих обходов, чтобы скрипт не конкурировал с живыми запросами интерфейса за очередь портала.
- `actions.v2.fetchList.make()` возвращает `AsyncGenerator<T[]>`. Каждая итерация `for await` отдаёт до `limit` записей (по умолчанию `50`) и использует курсорную пагинацию по `cursorIdKey` (по умолчанию равен `idKey`) в порядке возрастания — склейкой страниц занимается SDK.
- `Text.toB24Format(date)` преобразует JS-`Date` в ISO-формат, который Битрикс24 ожидает в фильтрах `crm.item.list`; «сырой» `Date` не сработает.

## Ограничения

- `crm.item.list` возвращает до 50 записей на страницу; это ограничение сервера, а не настройка SDK.
- Генератор **не** поддерживает собственный параметр `order`: курсорная пагинация требует сортировки по `cursorIdKey` (по умолчанию `idKey`) по возрастанию. Если указать `order` в `params`, во время выполнения появится предупреждение, а параметр будет отброшен.
- Обход останавливается после **10 000 страниц** — это 500 000 сделок по 50 на страницу — и выбрасывает `JSSDK_ACTION_MAX_PAGES_EXCEEDED`{lang="ts-type"}. Это страховка от «убегающего» обхода, а не предел для этого экспорта; если на портале действительно больше записей, передайте больший `maxPages`. Поскольку `fetchList` работает потоково, все страницы, записанные в CSV до этого момента, уже лежат на диске.
- Для v2-методов `idKey` по умолчанию равен `'ID'` (заглавными). Методы CRM-элементов возвращают `id` (строчными), поэтому переопределите его явно, как в примере. Если метод сортирует и фильтрует по полю с другим именем, чем возвращает (например, `tasks.task.list` сортирует по `ID`, а возвращает `id`), задайте также `cursorIdKey`; `crm.item.list` принимает имя строчными в обоих местах, поэтому этому скрипту нужен только `idKey`. Если ошибиться в этой паре, обход выбросит `JSSDK_ACTION_CURSOR_STALLED`, а не зациклится — см. [Ошибки](/docs/working-with-the-rest-api/errors/).
- Один экземпляр `B24Hook` соответствует одной учётной записи пользователя на портале. Если нужные сделки принадлежат другому пользователю, вебхук должен создать он сам (или учётная запись с доступом к данным других пользователей).
- Для очень больших периодов, которые исчерпывают дневной бюджет вызовов методов, разбейте диапазон дат на более мелкие части и запускайте их по очереди.
