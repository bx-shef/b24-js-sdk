## Что делает пример

Поднимает Express-эндпоинт `POST /webhook`, который сопоставляет события `ONCRMDEALADD`, `ONCRMDEALUPDATE`, `ONCRMDEALDELETE` с обработчиками. Каждый обработчик вызывает `crm.item.get`, чтобы дополнить данные (Битрикс24 присылает только ID сущности), и запускает вашу дальнейшую логику. Предоставляет эндпоинт `GET /health` для проверок оркестратора.

::note
**Безопасность.** Этот эндпоинт доступен публично. Примените два приёма защиты из раздела [Безопасность приложений-получателей событий](/docs/working-with-the-rest-api/security/): отвечайте `200` до проверки и сравнивайте `application_token` за постоянное время.
::

## Стек

Node.js 20+, `express`.

## Установка

```bash
pnpm add express
```

## Окружение

```bash
export B24_HOOK='https://your.bitrix24.com/rest/1/secret'
export PORT=3001  # default
```

## Запуск

```bash
npx tsx 07-webhook-handler.ts
# expose locally for tests:
npx ngrok http 3001
```

## Примечания

- Исходящие события Битрикс24 приходят как POST с `application/x-www-form-urlencoded`; парсер Express `urlencoded({ extended: true })` разворачивает `data[FIELDS][ID]` в `payload.data.FIELDS.ID`.
- Всегда сначала возвращайте `2xx`, а потом проверяйте и обрабатывайте. В Битрикс24 нет автоматического повтора (неудавшаяся или медленная доставка отбрасывается, а медленные обработчики получают более низкий приоритет), поэтому отвечайте быстро — см. [Приёмы безопасности](/docs/working-with-the-rest-api/security/).
- Регистрация событий выполняется один раз; `event.bind` / `event.unbind` из SDK см. в [рецепте 11 (регистрация исходящих событий)](/docs/examples/event-registration/).
- **В продакшене проверяйте источник запроса.** Задайте в `B24_APPLICATION_TOKEN` значение из консоли разработчика Битрикс24 (локальное приложение → application_token); рецепт сверяет с ним `payload.auth?.application_token` и молча отбрасывает несовпадающие запросы. Без этой защиты любой, кто знает ваш URL, сможет воспроизвести произвольные события.
