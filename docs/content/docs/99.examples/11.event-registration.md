## Что делает пример

Рецепт 7 (обработчик вебхука) предполагает, что события уже привязаны. Этот рецепт замыкает круг:

- `list` — выводит все события, привязанные на портале в данный момент
- `bind` — регистрирует целевой URL как обработчик для `ONCRMDEALADD`, `ONCRMDEALUPDATE`, `ONCRMDEALDELETE` (идемпотентно: повторная привязка той же пары ничего не меняет)
- `unbind` — удаляет эти привязки

Запустите его один раз после развёртывания обработчика и повторяйте при каждом изменении конфигурации.

## Стек

Node.js 20+. Внешних зависимостей нет.

## Окружение

```bash
export B24_HOOK='https://your.bitrix24.com/rest/1/secret'
export HANDLER_URL='https://your-server.example.com/webhook'   # нужен для bind/unbind
```

## Запуск

```bash
npx tsx 11-event-registration.ts list
npx tsx 11-event-registration.ts bind
npx tsx 11-event-registration.ts unbind
```

## Примечания

- `event.bind` возвращает код `ERROR_EVENT_BINDING_EXISTS`, если пара (событие, обработчик) уже привязана; рецепт считает это успехом, чтобы запуски были идемпотентными.
- `event.unbind` выбрасывает ошибку, если привязки нет; рецепт записывает это в лог и продолжает работу.
- У вебхука, через который вызывается `event.bind`, должно быть право доступа (scope) `event` (у входящих вебхуков, созданных в административном интерфейсе портала, оно есть).
- Для приложений, установленных через OAuth, аналог `event.bind` — привязка событий на уровне приложения через консоль разработчика или `event.bind` с авторизацией приложения.
