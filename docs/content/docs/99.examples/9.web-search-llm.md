## Что делает пример

В REST Битрикс24 нет собственного метода веб-поиска или LLM. Этот рецепт показывает шаблон «моста»: используйте для поиска и LLM любого внешнего провайдера, а затем отправьте ответ обратно в Битрикс24 через SDK. Обработчик записывает ответ LLM со ссылками на источники в таймлайн сделки как комментарий.

## Стек

Node.js 20+, `openai`. Веб-поиск — BYOC («принесите своё»): замените `webSearch()` вызовом Tavily, Brave, SerpAPI или любого другого провайдера.

## Установка

```bash
pnpm add openai
```

## Окружение

```bash
export B24_HOOK='https://your.bitrix24.com/rest/1/secret'
export OPENAI_API_KEY='sk-...'
export SEARCH_API_KEY='...'   # your provider's key
```

## Запуск

```bash
npx tsx 09-web-search-llm.ts <DEAL_ID> "<question>"
```

## Примечания

- Функция `webSearch()` в рецепте — заглушка. Замените её настоящим вызовом вашего провайдера; остальная часть рецепта не изменится.
- LLM получает указание отмечать каждый факт ссылкой `[N]`, где N — это `results[].id`. Рецепт добавляет к комментарию в таймлайне соответствующий список URL.
- `crm.timeline.comment.add` — классический метод API. Рецепт использует числовое значение `ENTITY_TYPE_ID: 2` (≡ `EnumCrmEntityTypeId.deal`): эта форма принимается на всех версиях порталов, которые мы проверяли. Строковая форма `ENTITY_TYPE: 'deal'` тоже работает на большинстве современных порталов; перейдите на неё, если вашей downstream-системе нужно символьное имя.
- Если вместо внешнего провайдера нужен AI Router под управлением VibeCode или поиск Битрикс, см. навык `b24jssdk-vibecode`.
