## Цель

Убедиться, что только что созданный входящий вебхук Битрикс24 доступен, проходит аутентификацию и имеет нужные права доступа (scope), прежде чем подключать его к чему-то более серьёзному. Скрипт вызывает `profile` и `app.info`, выводит ответы и при любой ошибке завершается с ненулевым кодом.

## Стек и требования

- Node.js 20+, ESM
- `@bitrix24/b24jssdk@^1.0.0`
- URL вебхука как минимум с правами доступа по умолчанию. Задайте его как `B24_HOOK`.

```bash
pnpm add @bitrix24/b24jssdk
export B24_HOOK="https://your-portal.bitrix24.com/rest/1/xxxxxxxxxxxxxxxx/"
```

## Полный пример

`scripts/b24-ping.mjs`:

```js
import { B24Hook, SdkError } from '@bitrix24/b24jssdk'

const hookUrl = process.env.B24_HOOK
if (!hookUrl) {
  console.error('B24_HOOK is not set')
  process.exit(2)
}

const b24 = B24Hook.fromWebhookUrl(hookUrl)

try {
  const profile = await b24.actions.v2.call.make({ method: 'profile' })
  const appInfo = await b24.actions.v2.call.make({ method: 'app.info' })

  const me = profile.getData().result
  const app = appInfo.getData().result

  console.log(`portal:    ${app.DOMAIN}`)
  console.log(`as user:   #${me.ID} ${me.NAME ?? ''} ${me.LAST_NAME ?? ''}`)
  console.log(`scope:     ${app.SCOPE?.join?.(',') ?? app.SCOPE ?? '(none)'}`)
  console.log('webhook is alive')
}
catch (error) {
  if (error instanceof SdkError) {
    console.error(`SDK error [${error.cause?.name ?? 'unknown'}]: ${error.message}`)
  }
  else {
    console.error(error)
  }
  process.exit(1)
}
```

## Запуск

```bash
node scripts/b24-ping.mjs
# portal:    your-portal.bitrix24.com
# as user:   #1 Anna Ivanova
# scope:     crm,user,im
# webhook is alive
```

URL вебхука, скопированный с опечаткой, приводит к ошибке 401, обёрнутой в `SdkError`, и скрипт завершается с кодом `1`. Сетевой сбой встроенный `RateLimiter` автоматически повторяет (`maxRetries` по умолчанию равен `3`, настраивается через `restrictionParams.maxRetries` — см. [Система ограничений](/docs/tools/limiters/)), и только потом ошибка передаётся наружу.

## Как это работает

- `B24Hook.fromWebhookUrl()` проверяет форму URL и достаёт из пути ID пользователя, секретный токен и имя хоста портала. Всё, что не похоже на `https://<host>/rest/<userId>/<token>/`, синхронно приводит к исключению — это защищает от опечаток.
- `actions.v2.call.make({ method })` — современный вызов одного метода. Он возвращает `Promise<AjaxResult>`; `.getData().result` — то, что Битрикс24 положил в `result` для этого метода.
- Ошибки приходят как `SdkError`, а исходная ошибка axios лежит в `cause`. Перехват этого класса позволяет отличить ошибки SDK от ошибок вызывающего кода.

## Ограничения

- У входящих вебхуков жёсткий лимит частоты (на момент написания — 2 запроса в секунду на пользователя на портале). Для задач сложнее проверочного запуска настройте `restrictionParams` — см. рецепт с выгрузкой.
- Метод `profile` возвращает пользователя, **от имени которого создан** вебхук, а не того, кто запускает скрипт. Подмены пользователя нет.
- Рецепт намеренно обходится без `try { … } finally { b24.destroy() }`: у `B24Hook` нет шага уничтожения. У `B24Frame` он есть, но это отдельная ветка кода.
