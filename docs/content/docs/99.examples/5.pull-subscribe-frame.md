## Цель

Приложение во фрейме, которое получает обновления от Битрикс24 в реальном времени: например, счётчик на значке растёт, когда приходит новое сообщение чата или дело CRM переходит к другому сотруднику. Клиент Pull объединяет транспорты WebSocket и long polling, а вы видите только один колбэк.

## Стек и требования

- Vue 3 + Vite (или Nuxt), запущенные внутри встройки (placement) Битрикс24
- `@bxshefby/b24jssdk@^1.0.0`
- На портале должен быть включён модуль Pull (он включён во всех облачных порталах и на большинстве порталов на собственной инфраструктуре)

```bash
pnpm add @bxshefby/b24jssdk
```

## Полный пример

`src/components/PullPanel.vue`:

```vue
<script setup lang="ts">
import { onBeforeUnmount, onMounted, ref } from 'vue'
import {
  initializeB24Frame,
  LoadDataType,
  LoggerFactory,
  useB24Helper,
  type B24Frame,
  type TypePullMessage
} from '@bxshefby/b24jssdk'

const logger = LoggerFactory.createForBrowser('PullPanel', import.meta.env.DEV)
const events = ref<Array<{ at: string, command: string }>>([])
let $b24: B24Frame | null = null

const {
  initB24Helper,
  destroyB24Helper,
  usePullClient,
  useSubscribePullClient,
  startPullClient
} = useB24Helper()

function handleEvent(message: TypePullMessage) {
  logger.info('pull', message)
  events.value.unshift({
    at: new Date().toLocaleTimeString(),
    command: message.command
  })
  // Keep the visible log short.
  if (events.value.length > 20) events.value.length = 20
}

onMounted(async () => {
  $b24 = await initializeB24Frame()

  // App + Profile are required so the helper can register a Pull channel.
  await initB24Helper(
    $b24,
    [LoadDataType.App, LoadDataType.Profile],
    'pull-panel-init'
  )

  usePullClient()
  // Listen to events from the `crm` module. Use `'application'` (default) for
  // your own app's custom events.
  useSubscribePullClient(handleEvent, 'crm')
  startPullClient()
})

onBeforeUnmount(() => {
  destroyB24Helper()
  $b24 = null
})
</script>

<template>
  <section>
    <h2>Live events</h2>
    <ul v-if="events.length">
      <li v-for="(event, index) in events" :key="index">
        <code>{{ event.at }}</code> — {{ event.command }}
      </li>
    </ul>
    <p v-else>Waiting for events…</p>
  </section>
</template>
```

## Запуск

Откройте приложение внутри Битрикс24, затем вызовите событие CRM в другой вкладке: перетащите сделку на новую стадию, добавьте дело, смените ответственного. В течение секунды команда события (например, `crm_deal_update`) появится вверху списка. Компонент показывает последние 20 событий.

## Как это работает

- `useB24Helper()` возвращает замыкание над единственным экземпляром `B24HelperManager`. Это **не** композабл Vue: он не читает хуки жизненного цикла Vue. Подключать его к `onMounted` / `onBeforeUnmount` нужно самостоятельно.
- `initB24Helper($b24, dataTypes, requestId)` загружает данные, которые нужны клиенту Pull для регистрации канала. `usePullClient()` (вызванный без явного `userId`) читает `profileInfo.data.id`, поэтому как минимум `LoadDataType.Profile` должен быть загружен заранее, иначе вызов выбросит `B24HelperManager.profileInfo not initialized`. Рекомендуется загрузить и `LoadDataType.App`, как в примере, чтобы менеджер получил полный контекст приложения.
- `usePullClient()` создаёт транспорт Pull (WebSocket с запасным long polling). `useSubscribePullClient(handler, moduleId)` регистрирует ваш колбэк для этого модуля. `startPullClient()` по-настоящему открывает соединение — вызывайте его последним.
- `destroyB24Helper()` разбирает транспорт и снимает подписчиков. Вызов при размонтировании не даёт WebSocket «утечь», когда слайдер приложения закрывается.

## Ограничения

- Порядок **обязательно** такой: `initB24Helper` → `usePullClient` → `useSubscribePullClient` → `startPullClient`. Вызов `useSubscribePullClient` до `usePullClient` выбрасывает `PullClient is not initialized`. Ошибка намеренная — она рано выявляет ошибки в связывании.
- `useB24Helper()` возвращает один общий экземпляр на замыкание. Если создать второй `useB24Helper()` и снова вызвать `initB24Helper`, второй вызов использует существующий менеджер, а не создаёт новый.
- `moduleId` по умолчанию равен `'application'`. Чтобы слушать модули портала (`'crm'`, `'tasks'`, `'im'`, …), передавайте их явно. Для подписки на несколько модулей нужно несколько вызовов `useSubscribePullClient`.
- События Pull доставляются по принципу «лучшее из возможного». Они хороши для сигнала «разбудить интерфейс», но не как источник истины. Если действие пользователя зависит от актуальности данных, всегда запрашивайте их заново через REST.
