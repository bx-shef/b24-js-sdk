## Что делает пример

Каждую минуту загружает открытые сделки (кроме `WON`/`LOSE`), сравнивает стадию каждой с ранее увиденным значением и при каждом отслеживаемом переходе (по умолчанию `EXECUTING`, `PREPAYMENT_INVOICE`, `FINAL_INVOICE`) создаёт задачу, привязанную к сделке через `UF_CRM_TASK`.

## Стек

Node.js 20+. Внешних зависимостей нет.

## Окружение

```bash
export B24_HOOK='https://your.bitrix24.com/rest/1/secret'
```

## Запуск

```bash
npx tsx 03-task-automation.ts
```

## Примечания

- Состояние (`dealStages`) хранится в памяти. Перезапуск его теряет — так задумано; в продакшене сохраняйте его на диск или в Redis.
- Опрос неэффективен при больших объёмах; вариант на Pull (подписка на события `'crm'`) есть в списке предложений.
- Порталы с несколькими воронками: рецепт использует помощник `baseStage()`, чтобы сопоставлять `C<n>:EXECUTING` и подобные стадии.
