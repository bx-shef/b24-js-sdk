## Что делает пример

Принимает ID сделки из командной строки, получает сделку (`crm.item.get` через `actions.v2.call.make`) и ленту её дел (`crm.activity.list` через `actions.v2.callList.make`). Отправляет GPT-4o структурированный запрос, просит рекомендацию в формате JSON и создаёт задачу (`tasks.task.add` через `actions.v3.call.make`), привязанную к сделке через `UF_CRM_TASK`.

## Стек

Node.js 20+, `openai`.

```bash
pnpm add openai
```

## Примечания

- Получение сделки — вызов **`restApi:v2`** (`crm.item.get`), который при этом использует поля в camelCase: `crm.item.*` пишется в camelCase по собственным причинам, а не потому, что это v3; в v3 методов `crm.item.*` нет. Список дел использует **классические** поля заглавными буквами (`OWNER_TYPE_ID`, `OWNER_ID`, `CREATED`). В `restApi:v3` правило — camelCase; см. [Обнаружение полей сущностей](/docs/actions/discovering-entity-fields/).
- Современный вариант — перейти на вызов инструментов OpenAI (параметр `tools`, цикл вызова функций); см. список предлагаемых примеров.
- Запрос требует строгого ответа в JSON и использует `response_format: { type: 'json_object' }`, чтобы это обеспечить.
- Соответствие приоритетов: `high → 2`, `medium → 1`, `low → 0` совпадает с перечислением приоритетов задач Битрикс24.
